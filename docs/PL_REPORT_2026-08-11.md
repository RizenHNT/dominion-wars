下面是 5 处不对的地方。我**不替 codex 决定要不要改、改成什么样子**，只把问题点出来交给他判断。

`AGENTS.md` 第 5 行还写着"Claude 是规划负责人"，但这段时间其实是 MiniMax（我）在代管。文件里完全没提我，没提我的配置文件 `minimax-pl.agent.md`，也没提"Claude 不在时 MiniMax 接管"这件事。

### 2.2 同一份文件完全没提新加的自动流程

AGENTS.md 里 Codex 那段只说"实现负责人"，没说 codex 还有"自动化执行"这一层（`codex exec --sandbox workspace-write` 那个口子）。DeepSeek 那段只说"测试负责人"，没说他在夜班里是"独立 QA，看真 diff 出报告"。

**→ 交给 codex 评估**：是否把 AGENTS.md 各角色段补一下夜班/白班的具体职责边界，让新人能照着做。

### 2.3 rehearsal 分支名字误导

git 里有个叫 `agents/nightshift-rehearsal` 的分支，看名字像是有独立的工作演化，但其实它**从来没自己提交过东西**，永远是"把主分支的最新内容拉过来"。叫"rehearsal"（排练）但实际是个镜像。

**→ 交给 codex 评估**：要不要把这个分支改名（比如 `worktree/nightshift-isolated`），或者干脆就当镜像用、把命名理由写进文档里。

### 2.4 定时器今天自己跑了一下，但失败了

`scheduler.log` 里 14:00 那次定时启动报了一个错："找不到 codex 这个程序"。意思是 codex 在电脑里装着的，但定时器不知道去哪个文件夹找它。这条修起来不复杂，但是**如果不修，以后每次定时都会失败**。

**→ 交给 codex 评估**：要不要加一个类似 `setup-deepseek-key.ps1` 的小脚本（`setup-paths.ps1` 之类），把 codex 路径登记下来；或者在 `run-nightshift.ps1` 里加一个启动前自检。

### 2.5 之前 Unity 重建方案还在草稿状态，没正式交给 codex/DeepSeek 复审

8 月 9 号那份 `docs/PROPOSAL_FORGE_M1.md`（Unity 重建提案），文件已经写好放在那，但 codex/DeepSeek 还没正式回头复核第 8 节"5 核心路径"和第 9 节"首切片验收"。没有这份复审，Do 阶段的子任务（写 SPEC.md、写卡牌数据规则、写效果动作清单）都还没法正式开工。
