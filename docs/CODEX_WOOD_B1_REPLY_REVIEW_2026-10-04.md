## 1. 有依据的发现

- `src/Data/CardCatalog.cs:194–202` 对 punish > 0、且两个惩罚字段均未声明的卡自动设置 `punishActivatable=true`、`punishCost=punish`。当前木卡共 21 张，其中 16 张满足此条件。这与 `docs/RULES.md:57` 的“不能仅因惩罚值大于 0 获得能力”冲突。
- `src/Engine/Turns/PlayCardActionHandler.cs:141` 在 PunishActivated 时选用 PunishEffects、否则选用 OnPlayEffects。因此上述默认值结合空 PunishEffects，确实能导致普通效果被丢掉。本次未重新计算“62%”统计，不能把所有无 BUFF/无成长的出牌都算作错误空发。
- Java `CardDef.java:305–306` 对惩罚能力的默认值是卡类型 PUNISH、惩罚费用默认为 0，没有同一条按 punish > 0 自动开启的分支。这里只验证这个默认值差异，不宣称 Java 整体已经与惩罚降临 v2 完全一致。
- `runs/leader-events/events.jsonl` 的 seed 1：统领登场 event 18 后，event 22/23/24 均为 BUFF 的 EFFECT_SKIPPED，原因 target.none。`EffectRuntime.Cards.cs:418` 新建统领上下文没有 selectedTargetId；候选多于一个时 `EffectTargetResolver.ResolveSingle` 不自动挑选。这个案例的跳过有依据，但“全部单目标效果始终被跳过”表述过度：没有显式目标且候选恰好只有一个时当前 resolver 会解析该候选。

额外缺口：`RULES.md:63–66` 已区分普通效果后追加惩罚效果、纯折扣和变更替换。当前上述二选一路径不能完整表达这套规则。仅关闭 16 张卡的自动能力，或者给空列表补日志，不等于修好了明确声明的折扣型/叠加型卡；实现交接应覆盖这个语义问题。

## 3. 多段强化证据引用错误，逐段独立选目标也尚未实现

报告 §3.6.1 引用的 event 70、76、437 确实作用于同一实例 124，但前两条在 turn 3，后一条在 turn 9，而且来自仅替换统领、保留生产卡组的运行。这只能证明同一随从跨出牌/跨回合可继续强化，不能证明一张新卡的多段结算。

当前 `PlayCardActionHandler` 在 Prepare 时解析一次 targetId，并在约第 299 行将一个 SelectedTargetId 放入整批 EffectContext；`EffectTargetResolver.cs:40` 每条 FRIENDLY_MINION 都读取这个同一 ID。

所以必须区分：

- 同一批有多条 BUFF，并作用于同一选定目标：当前结构能够表达，仍应提供新卡一次出牌的连续事件复现。
- 每条 BUFF 都让玩家独立选一个目标：当前路径没有该能力，不能把它写成已实现。
- 单目标效果与 ALL_FRIENDLY_MINIONS 群体效果：可以并存；与逐段独立选目标是不同问题。

新卡复现至少保留一次 CARD_PLAYED 到对应结算结束的连续事件，标明 source/rootEventId、选定目标、每段 amount、前后生命。对统领被惩罚抽到的目标选择，需保持响应窗口和隐藏信息边界，不能用默认选第一只代替玩家选择。
