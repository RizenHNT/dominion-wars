**日期**：2026-09-13
**段**：A 成长轴（对应 `docs/PL_WOOD_POOL100_SPEC_2026-09-13.md` §1 表）
**设计依据**：规范 §0.1–§0.6 + `data/cards/wood.json` 现有 21 张 + `src/main/java/com/dominionwars/engine/Effects.java`（增幅/封印/条件的唯一真源）

> 唯一代价轴是 **惩罚值 `punish`**。因此本文所有「0–2 费 / 2–6 费 / 6–8 费」一律指 **惩罚值**
> （打出后对方立即抽等同张数）。表中 `punish` 列即该卡的「费」。

| # | 病症（实测） | A 段的对策 | 由哪些卡承担 |

| P1 | **前 5 回合轴上恒为 0**，玩家看不到任何反馈 | 把「第一个封印体」压到 0–2 惩罚值、第 1–2 回合就能落地；无条件、无门槛 | 拓荒者之种 / 落地生根 / 新芽园丁 / 苔庭守卫 / 扎根 / 年轮 |

### 战略角色分配（8 / 10 / 8 / 4 / 4 = 34）

| 组 | 张数 | 惩罚值带 | 职责 |
|---|---|---|---|
| 一、铺陈者 | 8 | 0–2 | 第 1–2 回合就让轴上出现**非零数字**，并开始爬扎根阶梯 |
| 二、阶梯随从 | 10 | 2–6 | 卡面写出`若扎根≥n`的门槛，逐档解锁，把「扎根 N」变成玩家看得见的进度条 |
| 三、增幅器 | 8 | 2–6 | 把封印体生命往上推；**重点是 8–64 的中步**，不是再堆一次几百 |
| 四、续轴与重建 | 4 | 2–6 | 封印体被打掉后**重新起轴**；同时给封印体抗破坏手段 |
| 五、终结者 | 4 | 6–8 | 把 456 的中位数推过 512，或直接把「已铺好的轴」变成胜利 |

### 三条硬设计约束（我在每张卡上都遵守）
1. **`BUFF` 一定会吃增幅**：只要来源是古木且目标是己方，`effective = (base + root) × 2^min(3,rampant) ≠ base` ⇒ **该随从被封印**（攻击归 0、失去全部关键词）。
   所以 A 段所有 `BUFF` 都是**有意的封印动作**，没有「白拿加成还不封印」的写法。反过来，我也**不给即将被强化的随从挂关键词**——那会被封印吃掉。
2. **治疗封顶在 maxHealth，不能推轴**。所以 `HEAL` 只用于「先 `BUFF` 抬高上限、再在同一张卡里 `HEAL` 补满」的复合写法（泉眼德鲁伊 / 苔藓圣餐）。
3. **条件逐效果独立求值**（`Effects.resolve` 逐个检查 `EffectSpec.condition`，不满足只跳过该条）——这是我做「阶梯卡」的机制依据，不是猜测。
4. **每条效果各自选目标**（`pickTargets` 按 `EffectSpec` 逐个解析，引擎没有「同链锁定同一目标」的写法）。所以阶梯卡（年轮秘仪 / 世界树幼苗 / 藤心绽放）的卡面**逐段写明要选哪个随从**，不写成「它」；实体选择两次都能落到同一个封印体上，卡面与引擎因此一致，不需要新引擎工作。

## 六、tag 预算与专属 tag 台账（RULES §13.5：专属 tag 全池 ≤3）

**专属 tag 恰好 3 张**，且都是「拼成完整词」的独立新 tag（不与现有 tag 池的 `恢复/守护/结界/…` 撞车）：

`恢复 4 / 古树 4 / 树灵 3 / 世界树 3 / 守卫 2 / 荆棘 2 / 野兽 2 / 增强 2 / 守护 2 / 结界 2 / 仪式 2 / 苔藓 2 / 德鲁伊 1 / 菌根 1`（14 个 tag，覆盖 38 个 tag 槽 / 34 张卡）

其中高频 tag 都落在**低影响或低频率卡**上（`恢复`＝4 张全是辅助位：`落地生根`/`扶根`/`盖亚之赐`/`新芽再生`；
`古树`＝`古根屯积`/`年轮巨像`/`根脉巨像`/`世界树之环`，全部是 3 惩罚值以上的重卡，一回合本来也只会出一张）。
**收益最高的卡要么无 tag**（`扎根`、`年轮`、`古木滋养`、`疯长盛放`、`无根返青` —— 一回合可重复打出，代价是占用出牌与手牌），
**要么双 tag**（`古根屯积` 古树+树灵、`苔皮巨兽` 野兽+苔藓、`世界树之环` 世界树+古树）。

1. **无 tag = 一回合可重复打出**：`扎根`、`年轮`、`古木滋养`、`疯长盛放`、`无根返青` 都靠这一点成为「稳步走」的主力。
2. **单 tag = 一回合一次**：门槛卡/阶梯卡用单 tag，防止同回合把整条阶梯一次刷穿。
3. **双 tag = 一次锁两个种族**：只给数值明显超线的大卡（`古根屯积` / `苔皮巨兽` / `世界树之环`）。

## 八、`engineCost: 大` 清单

**本段没有 `engineCost: 大` 的卡。** 为可测性，我主动放弃了下面 3 个方案，并记录了它们各自缺什么 —— 若 owner 想要这些角度，可以直接作为 B/C 段或后续批次的输入：

1. **「封印自己换资源」（封魂方向）** —— 需要 **`SACRIFICE`/`SEAL_SELF` 类动作**，把「己方一个随从 → 封印」当作**成本**而非增幅副作用。
   缺失：`EffectAction` 里没有「主动封印己方目标」的动作（`BUFF` 走的是增幅触发封印，基础值为 0 时 `applyGrowth` 直接返回 0、不封印，见 `Effects.java` L279/L482）。
2. **「年轮剥离」：按目标身上的层数结算伤害** —— 需要 **`刻痕`(engrave) 状态字段 + 以层数为 amount 的读取器**。
   缺失：`EffectSpec.amount` 是固定整数，引擎没有「amount = 目标某状态层数」的读取路径。
3. **「封印体阵亡时的补轴触发器」** —— 需要 **同归/离场触发挂点**（`onDeathEffects`）。
   缺失：`cards.schema.json` 只有 `onPlayEffects / chantEffects / ambushEffects / punishEffects / onOpponentDiscardEffects / commit|push|pullEffects`，没有离场触发挂点；本文改用 `无根返青`+`新芽再生` 这两张**主动补轴卡**替代。

> 这三条都不是 A 段必须的：A 段的目标是「保证卡组能赢、推进 512、稳定不超模」，上面 34 张已经全部落在 §0 的合法词表内，落数据后可以直接跑 `WoodDesignProbe` + 配对矩阵，不需要先等引擎扩展。
