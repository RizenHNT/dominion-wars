### 2.2 winParam 跨栈断裂 — 事实核验（PL 独立验证，非引用）

| 层 | 行为 | 位置 |
|---|---|---|
| Java CardDef | 只读 `winParam`（默认 0），**无 winAmount 兼容** | CardDef.java:103 |
| Java Game | `opp.totalDiscarded >= ld.winParam`，winParam=0 时恒真 → 首领秒胜 | Game.java:971 |
| C# CardCatalog | 读 `winParam`，缺失则回退 `winAmount`（双字段兼容） | CardCatalog.cs:140-146 |
| .NET 内部模型 | 已统一 `LeaderWinParam` 命名 | CardDefinition.cs / ContractDtos.cs / EngineProjectionAdapter.cs |
| Schema | LeaderDef 同时允许 `winAmount` 与 `winParam`（均 integer 0-999），required 仅 `winCondition` | cards.schema.json `$defs.LeaderDef` |
| 当前引擎数据 | `data/cards/*.json` 已用 **winParam**（machine_alpha=15 / sea_leader=18 / wood_leader=7），winAmount 计数为 0 | data/cards/machine.json / sea.json / wood.json |
| 设计包 bundle | 用 **winAmount**（machine=6 / sea=12 / wood=512），未导入引擎数据 | docs/卡牌设计包_2026-08-15/bundle_v2.json |

**结论**：断裂为**潜在风险**，非当前活跃故障。当前 `data/cards/*.json` 引擎数据全部使用 winParam，与 Java/C#/.NET 均一致，现有链路无 bug。风险仅在 **bundle（winAmount）未来导入引擎数据**时触发：若导入路径是 Java（历史库存）则 winParam=0 → 秒胜。C# 路径因双字段兼容可正常兜底。

### winParam 推荐意见（PL 立场，最终以人类/Codex 定夺为准）

**推荐方案 ③：schema 统一单字段 `winParam`**，理由：

1. **.NET 为当前运行权威**，Java 已降级为历史库存（不再新增行为）；.NET 内部已用 `LeaderWinParam` 命名。
2. 当前引擎数据 `data/cards/*.json` 已全部使用 `winParam`，schema 统一后零迁移成本。
3. 未来 bundle 导入时需将 `winAmount` 翻译为 `winParam`（数据层转换，无运行时代码改动）；bundle 本身是设计源文件，暂不改动，仅作为导入约定。
4. 可选兜底：保留 C# `winAmount` 回退 1 个版本，避免历史数据意外破坏；Java 因已冻结不必补兼容。

**待办移交**：

- **Codex**：schema 统一为 `winParam` 并同步导入工具（数据层，非运行时）。
