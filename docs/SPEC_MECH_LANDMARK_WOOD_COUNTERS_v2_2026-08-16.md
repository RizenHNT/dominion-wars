## 一、机械地标（护符，炉石地标型）

### 1.1 地标定义

机械统领以**护符（地标）**形态在场：非随从、不攻击、不能被直接攻击，作为地标存在。**不用咏唱发动**，而是**接收下载（Pull）获得效果**。

### 1.2 下载费用（人类定义："上传下载都需要费用"）

- **上传（Push）需要费用**：每次上传支付费用。
- **下载（Pull）需要费用**：每次下载支付费用。
- 机械卡**出牌费 = 0**（全家 0 费，RULES §12.4 L258 基线）。
- 上传/下载费用是**独立于出牌费的机械动作费**（引擎 Pull/Commit 当前不扣费，需补）。

### 1.3 地标效果（人类重写格式，原文照录）

```
下载1（需要对面抽1使用下载）：
  本卡根据下载层数X获得效果
    1层：本局下载惩罚降为0
    2层：获得【吟唱1】：召唤【上古机神alpha】
```

**语义展开**：
- **下载层数 X**：地标每被下载（Pull）一次，层数 +1（**地标独立计数器**，人类 2026-08-16 定稿，不复用 PullCount 以避免与胜利计数混淆）。
- **1 层**：本局下载惩罚费用降为 0（永久豁免下载动作费）。
- **2 层**：地标获得【吟唱1】（chant=1，引擎已实现结束阶段倒计时），吟唱完成后**摧毁本护符，召唤【上古机神alpha】**（随从登场）。
- Alpha 登场后，继续下载以达成胜利条件（PULL_TOTAL_GE）。

### 1.4 机械惩罚牌（人类定义："被喂时上传本张卡(1)来使用"）

- 机械 PUNISH 卡：出牌费 = 0（全家 0 费）。
- 被惩罚抽到（被喂）时：**上传本张卡（费用1）来使用**——即被喂时不直接打出，而是"上传（1费）"后结算。
- 这样：不违反"全家0费"（出牌费0），实际使用路径花费 1 费（上传费）。

## 二、古木计数器（人类澄清：扎根/疯长/封印早就定了，我之前 spec 写错）

### 2.1 扎根 rootStacks（加法叠层）

- 使用**扎根卡** → rootStacks +1（累计叠层，**不消耗**）。
- 每层强化 **+1/+1**：1 层 = +1/+1，2 层 = +2/+2，N 层 = +N/+N。
- **⚠️ 修正**：RULES §12.2 现写"基础 + 层数×4"是**错的**，人类明确是"每层 +1/+1"。需同步改 RULES。

### 2.2 疯长 rampantStacks（乘法倍增）

- 使用**疯长卡** / wood_leader 提供 → rampantStacks +1。
- 每层强化 **×2**：1 层 ×2，2 层 ×4，3 层 ×8（= 2^层）。上限 3 层（引擎已限 0-3 ✅）。
- 与 RULES §12.2 一致，无需改。

### 2.3 封印 sealed（保留）

- 受扎根/疯长**增幅强化**的目标进入 `Sealed=true`：攻击归 0、不能攻击、能力失效（仅保留身份/归属/区域/生命/生命上限）。
- 普通 buff（无增幅）不触发封印。
- 胜利判定 GIANT_HEALTH_GE 已就绪（EndPhase.cs:155：Sealed && Health >= winParam）。

## 四、机械费用拆分（人类 2026-08-16 定稿）

### 4.1 费用拆分规则（人类定义："把原本的出牌惩罚值分给上传下载，根据强度分配"）

- 机械卡**出牌费 P = 0**（全家 0 费）。
- 卡的强度价值 = 原本出牌惩罚值预算（按风险定价凸函数），**拆分成两个动作费用**：
  - **上传费用（uploadCost）**：上传（PUSH）动作需支付。
  - **下载费用（downloadCost）**：下载（PULL）动作需支付。
- **无统一费用表**，每张卡按自身强度分配（策划逐个定，Codex 实现字段即可）。
- 引擎 Pull/Commit 当前不扣费 → 需补动作费用结算。

### 4.2 机械卡字段（schema 需补，Codex 实现）

| 字段 | 类型 | 语义 |
|---|---|---|
| uploadCost | int | 上传动作费用（≥0） |
| downloadCost | int | 下载动作费用（≥0） |
| commitEffects | EffectSpec[] | 提交时触发效果 |
| pushEffects | EffectSpec[] | 上传时触发效果（可选，默认无） |
| pullEffects | EffectSpec[] | 下载时触发效果（写在卡自身，固定值，无 X 动态引用） |

### 4.3 下载效果方案（2026-08-16 策划定稿：卡自身固定值，目标限机械）

```
机械士兵
上传1
提交：召唤一个0/1的机械生命体
下载1：+1/+1
```

**机制（B 模式，2026-08-16 人类确认：出牌 ≠ 提交）**：
- 每张机械卡声明 **提交费用（commitCost）+ 上传费用（uploadCost）+ 下载费用（downloadCost）+ 提交效果（commitEffects）+ 下载效果（pullEffects，写在卡自身，固定值）**。
- **生命周期**：出牌（0费，进场当普通随从，可攻击/可被攻击）→ **手动提交**（付提交费 + 触发提交效果，卡离开场上进提交队列）→ 结束阶段**自动上传**（付上传费，进云端栈）→ **下载**（付被下载卡的下载费 + 触发该卡下载效果）。
- **下载需要下载载体**（2026-08-16 人类定稿）：下载动作的执行者是**己方场上的机械单位**（tag="机械"，如提交时召唤的机械生命体）或**机械统领地标**。**无载体 → 下载不可发起**（不推进胜利计数）。
- **下载动作**：选云端栈顶卡 → 支付其下载费用 → 载体获得该卡的下载效果（强化目标=载体）。
- 后续新卡可打破"目标限机械"限制（人类预留例外口）。

**示例语义（B 模式）**：
- 机械士兵：出牌 0 费 → **上场当随从** → 手动提交（付提交费 + 触发提交效果：召唤 0/1 机械生命体，召唤物留场上）→ 上传付 1 费。
- 下载机械士兵：支付其下载费 1 → 下载载体（机械生命体或地标）+1/+1。
- 下载策略 = 选云端哪张卡（每张效果不同）+ 选哪个机械单位受强化。
