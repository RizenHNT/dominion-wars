## 核心结论：B1′ 仍受旧加载器缺陷影响

`build-output/wood-design-2026-10-04/runs/big-prod-fixed/run.json` 与 `runs/fixed-b1prime-v2/run.json` 均记录驱动为 `build-output/dynamic/probe/PlCsim.dll`，SHA256 为 `11C34F177DD4BE6E5830B65D757F6DD260168344469E0583DD75AF163D334929`。

直接用该目录现存 `DominionWars.Data.dll` 加载 `pool-b1prime`，得到：

| 卡 ID | PunishActivatable | PunishCost | 普通效果数量 | 惩罚效果数量 |
|---|---:|---:|---:|---:|
| wood_b1_bloom | true | 3 | 2 | 0 |
| wood_b1_yearring | true | 5 | 3 | 0 |
| wood_b1_moss_warden | true | 2 | 1 | 0 |
| wood_b1_regrow | true | 2 | 2 | 0 |

当前 `src/Data/CardCatalog.cs:194-195` 已采用 `type == "PUNISH"` 的能力默认值与 0 的费用默认值。但上述实际程序集仍对未显式声明的普通卡自动授予惩罚降临能力。生产的 16 张卡已显式配置 false，实验新增四张仍会中招。

这证明 B1′ 的 67.5% 不能用于评判设计改动收益。它不证明四张牌每次打出都空发：具体是否进入错误模式仍取决于出牌来源；必须用出牌事件核对。现有加载状态已经足以否定“修复后两个版本同条件”的前提。

复现：在独立 PowerShell 进程先用 `[Reflection.Assembly]::LoadFrom` 加载该目录的 Newtonsoft.Json、Engine、Data 三个 DLL，然后调用 `[DominionWars.Data.CardCatalog]::LoadDirectory` 加载 `pool-b1prime`，检查四张卡的上述字段。不要在已加载另一个版本程序集的进程内混测。

## 日志数字与比较口径

生产 240 局：192 胜，80.0%；平均回合 5.9458，中位回合 6。日志中按 `winner=0` 且 `reason=win.giant_health_ge` 统计成长胜利为 **187**；按 `max_sealed_health>=512` 统计为 **186**。两者不同，需要解释采样时点，不能互相替代。

B1′ 120 局：81 胜，67.5%。按 `(leader1, seed, first_player)` 与生产日志匹配，生产对应 120 局为 **94 胜，78.33%**。所以样本一致时的描述性差距是 **10.83 个百分点**，不是直接以生产 240 局计算的 12.5 个百分点。两组又分别是 60 与 54 张主牌，并同时换入多张新卡和新统领；即使修复程序集，也不能把这组差距归因于某一张卡或费用。

三种对手在生产日志中分别为古木 79/80、65/80、48/80。该分布是值得优先复核的强烈信号，但测试仅古木座位 0、default 策略；尚不是全部四阵营、多个策略下的最终平衡结论。

## DS 需要更正的推断

1. 疯长并非无上限：`src/Engine/Effects/EffectRuntime.State.cs` 的 AddRampant 使用 `Math.Min(3L, ...)`，上限 3。扎根与疯长要分别分析。
2. “增加惩罚值没有用”未经对照实验支持。惩罚是对手抽牌及响应资源的一部分，不能只分析古木自己的速度。
3. 烈焰对古木 1/80 不足以证明“烈焰存在独立于古木的缺陷”。先补烈焰与其他两阵营对局，再分离卡组、策略、实现和对局机制的影响。
4. 四阵营共有 6 个不重复配对；含古木 3 个，剩余 **3 个**，不是 5 个。
5. `build-output/pl-csim/Program.cs` 已支持 `--cards-dir` 和 `--decks-dir`。优先使用经验证的新构建及通用模拟器，不应把 WoodProbe 的限制直接说成没有可用的非古木测试路径。
6. “8–12 回合”是待论证的体验目标，不能依据已作废历史基线直接定为验收规则；均值与中位数不能混用。80 局接近 50% 时一个标准误约 5.6 个百分点，不是 95% 置信范围，也不证明 45%–55% 等价。
7. 不要从当前结果直接升级到新增消耗/清除扎根规则。先用已实现的攻击、移除、费用和成长参数做受控实验，提出规则改动时明确属于待 owner 决策的产品提案。
