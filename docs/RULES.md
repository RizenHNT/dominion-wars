# 《统御战纪》规则书（v1.0 · 规范化整理版）

本规则书分为两层：

1. **已启用规则**：当前对局使用的基础规则与已确认裁决。
2. **候选机制规范**（§12）：已经统一术语和设计边界、但尚未完成数据、引擎、快照与测试接入的后续机制。

§12 不改变当前可运行对局，也不能被客户端当作已实现功能。所有数值默认值均可在 data/balance.json 中调整；候选机制的数值在正式启用前另行冻结。

本次整理只修改规则文案，没有修改运行时、卡牌数据或合同。规则语义与实现出现差异时，必须先完成实现一致性修复和测试，才能宣称对局已符合本规则书。

## 1. 对局目标

**基础胜利方式：击败对方可被击败的统领。**

- 除胜利条件明示可以绕过门限外，在双方统领都降临之前，对局不可能分出胜负（门限保护：任何会致败的数值在此期间最低钳制为 1）。
- ROYAL_CASTLE_BREAK 是明确的门限例外：王城可以在双方统领尚未全部降临时被击破，并依照 §9.1 召唤统领、结算对应胜利条件。
- **牌库循环胜负**是基础胜利方式之外的已启用特殊规则：任一玩家因对手的有效牌库循环而累计获得胜利计数，达到上限（默认 10 次）时获胜，详见 §9。
- 统领可附带**特殊胜利条件**（见 §7），达成后立即结束对局。
- 未在本章或 §7、§9 明确列出的条件，不得作为胜利条件；§12 中的候选机制不会自动产生胜负。

## 2. 卡牌类型

| 类型 | 说明 |
|------|------|
| 随从 | 具有攻击力/生命值，降临后可参与战斗 |
| 咒文 | 打出立即结算；可带【吟唱 X】：先入场等待 X 回合后才结算 |
| 伏击 | 伏击阶段盖放，对方执行特定动作时触发 |
| 惩罚牌 | 默认无法主动打出。只能在被惩罚抽到且满足条件时发动，效果强力；若以非惩罚途径抽到，本回合结束阶段自动销毁 |

任何类型的卡都可以在定义中声明【惩罚降临】（punishActivatable，旧称"惩罚响应"），获得“被惩罚抽到时可发动”的能力。仅有惩罚值大于 0，不足以自动获得该能力；是否可触发必须由卡牌定义明确声明。

## 3. 惩罚值系统（核心机制）

- 每张卡都有**打印惩罚值**（printedPunish / P，自己回合费用）。在当前基础规则中，打出卡牌会使对方立即抽取等量的牌；实际抽牌数量称为**有效惩罚值**（effectivePunish）。
- 先驱威压、卡牌效果或其他已批准修正可以改变 effectivePunish，但不得把卡牌定义中的打印值悄悄改写成另一张卡的定义。
- **惩罚降临（v2，2026-08-15 定稿）**：卡被惩罚抽到（对方喂牌）时立即可用——支付**惩罚降临费用**（punishCost / P'，对面回合费用）后打出，**替代打印惩罚值作为费用**；结算顺序为**触发普通效果 → 追加惩罚效果**（§13.5）。
  - **折扣型**：惩罚降临仅降低费用，无额外惩罚效果（如 growth 惩罚降临 0 = 被喂时 0 费使用）。
  - **叠加型**：普通效果 + 追加惩罚效果均结算（白送追加，预算须卡紧）。
  - **替换型（"变更为"）**：惩罚触发时普通效果被变体替换，只结算变体。
  - **伏击卡不设惩罚降临**（盖放机制与惩罚追加相违背）。
- 惩罚降临效果可能再次使另一方抽牌并形成连锁。规则模型允许递归，但实际结算最多 20 层；达到上限时必须停止继续展开，不得静默继续。
- 发动惩罚降临前，还须校验该卡惩罚值以外的其他条件（如“敌方随从 ≥ 2”）。

惩罚值是当前基础规则的主要风险轴，不等同于独立的法力费用。除非另有正式规则，Cost 字段不构成当前对局的第二套费用系统。

### 3.1 空发裁决

- 若你打出卡牌时其惩罚值大于对方卡组剩余张数：允许打出，但该牌**空发**——计为使用、消耗词条、效果不结算、对方不抽牌，并且你强制进入弃牌阶段结束回合。
- 惩罚值恰好等于对方卡组余量：合法，正常结算抽空对方卡组；之后你仍可继续打出惩罚值为 0 的卡。
- 对方回合中因惩罚发动造成的空发，不会结束任何人的回合。
- 对方卡组无牌时，对局进入“强制结束当前回合”状态。

### 3.2 先驱威压

当**仅一方**统领在场时：

- 对方所有卡牌惩罚值 +1（pioneerOpponentPunishBonus，默认 1）；
- 统领方弃牌上限 +2（pioneerHandLimitBonus）；
- 备选配置：统领方自己的卡牌惩罚值 −N（pioneerSelfPunishDiscount，默认 0）。

设计意图：让先打出统领成为明确收益，避免双方互相憋统领拖慢节奏。

## 4. 词条限制

- 每张卡可带若干词条（如“破坏”“弃牌”“恢复”）。
- 同一玩家的同一词条，每个“回合段”只能使用一次。“回合段”指两次玩家交替之间的全部时间——每当回合从一名玩家转移到另一名玩家时，双方的词条使用记录全部重置。
- 伏击牌的词条在触发时消耗（盖放不消耗）；惩罚值则在盖放时支付。
- 资源、计数器和临时状态必须明确归属（玩家、统领、卡牌或特殊区域）、可见性、持续时间和清除时点。客户端只显示引擎提供的状态，不自行推导胜利、合法性或结算结果。

## 5. 回合结构

开始阶段（抽牌；卡组空则洗牌） → 伏击阶段（可盖放） → 行动阶段（出牌/攻击） → 弃牌阶段（超过上限须弃至上限） → 结束阶段（吟唱推进、惩罚牌销毁等） → 交替

默认数值：起手 5 张，每回合抽 1 张，后手第一个回合额外 +1 张，手牌上限 8。构筑采用 **59 张主牌 + 1 张统领**，合计 60 张；统领不占 59 张主牌名额。

- 弃牌阶段的**强制弃牌不计入**“对方累计弃牌”类胜利条件；只有效果造成的弃牌与惩罚转化弃牌计入（防止挂机自动达成）。

## 6. 伏击

- 每回合限盖放 1 张；每个敌方动作最多触发 1 张伏击响应。
- 三种类型：
  - **普通**：可在伏击区累积多张；
  - **专注**：触发的回合压制你其他所有伏击（不可再触发）；
  - **封场**：盖放期间你不能再盖放其他伏击。

## 7. 统领牌

- 每卡组必含 1 张统领，开局正面朝上洗入卡组。
- 任何手段（含被惩罚）抽到统领，立即自动降临：随从统领进战场，非随从统领进统领区（伏击统领进伏击区）。
- 被惩罚抽到统领会额外触发其强力惩罚效果。
- 统领永不离场：摧毁、退场、变形等效果对统领一律空发；唯一例外是统领自身效果使其离场（如伏击统领触发后洗回卡组）。
- 统领能力按字段拆分（win_condition / entrance_effect / passive_effect / activated_ability），详见 §11.2。
- 统领的存在形式（由其定义决定）：
  - 随从统领：以攻/血战斗，生命归零时被击败；只有随从型统领能够通过“被击败”产生胜负，因此其卡面能力可以具有更高的强度预算；
  - 耐久统领：自身耐久归零则败北（非“被击败”，是其耐久资源耗尽）；
  - 赋予生命统领：给予玩家生命值，生命归零则该方败北（非“被击败”，是己方生命资源耗尽）；
  - 伏击统领：降临后进入伏击区，按照卡面声明的触发条件结算；除非卡面另有说明，否则不作为战斗目标。
- 非随从统领不可通过“被击败”触发胜负；其胜利必须来自统领定义中明示的 winCondition，其败北则按该形态明示的资源或规则结算。
- 统领可附带特殊胜利条件，例如：
  - OPP_DISCARD_TOTAL_GE n：对方累计（受效果）弃牌 ≥ n；
  - NO_DAMAGE_TURNS_GE n：己方连续 n 个回合未受任何伤害；
  - OPP_PUNISH_DRAW_TURN_GE n：对方单回合内因惩罚抽牌 ≥ n 张；
  - AMBUSH_TRIGGER_WIN：伏击统领的明示触发条件达成；
  - ROYAL_CASTLE_BREAK：王城被破坏即触发持有该条件的首领获胜（被动，不问谁破城；当前仅 flame 持有，见 §9.1）；
  - **GIANT_HEALTH_GE n（新增）**：己方封印随从生命 ≥ n（木养巨物，当前 512）；
  - **PULL_TOTAL_GE n（新增）**：己方累计下载（Pull）结算 ≥ n 次（机械下载轴，当前 6）；
  - **OPP_PUNISH_TRIGGERED_GE n（新增）**：对方累计成功发动惩罚降临 ≥ n 次（命运连锁）。
- 统领的特殊胜利条件必须在统领定义中明确声明；未声明特殊条件的统领仍使用基础胜利方式。候选机制不得通过隐藏计数器自动增加新的胜利条件。

## 8. 战斗

- 随从每回合可攻击次数为卡牌字段（默认 1）。
- 召唤当回合不可攻击（**突袭**除外）。
- 关键词：
  - **突袭**：召唤当回合即可攻击；
  - **嘲讽**：对方必须优先攻击嘲讽随从；
  - **圣盾**：抵消受到的第一次伤害；
  - **扰魔**：不能成为咒文/惩罚效果的目标；
  - **永续**：标记型关键词，配合永续光环类效果。

## 9. 牌库循环与胜利计数

- 开始阶段卡组为空时，将墓地洗回卡组（可配置是否包含手牌），称为一次有效牌库循环。
- 某玩家发生有效牌库循环时，其对手的胜利计数 +1。
- 一方胜利计数达到上限（默认 10）即获胜。
- 个别效果（如机械阵营）可使“下一次牌库循环不增加对手胜利计数”。
- 王城被击破时，破城方自己的胜利计数设为至少 9。

### 9.1 王城

- 王城是双方共用的公开中立单位，位于战场中央，不属于任一玩家。
- 王城没有攻击力，不能攻击；它拥有一条共享的高额生命值，默认初始生命为 75。该数值属于可调平衡参数，不改变王城的规则身份。
- 王城只接受明确允许以王城为目标的伤害、恢复和强化效果。生命强化同时提高当前生命与生命上限；恢复只补充当前生命，不能超过生命上限。除非效果明确声明作用于王城，普通的摧毁、变形、关键词授予等效果不得把王城当作一般随从处理。
- 王城在目标与战斗处理上原则上视为特殊随从。进攻方仍受嘲讽等目标限制约束：存在必须优先攻击的嘲讽目标时，不能绕过它攻击王城。
- 王城生命归零后被击破。破城方的胜利计数设为至少 9，并叫出破城方自己的统领，使对局进入高压收尾阶段。
- 击破王城本身不直接等同于立即获胜：王城被破坏会触发持有“王城被破坏”胜利条件的首领获胜（被动触发，不问谁破城；如 flame 的 ROYAL_CASTLE_BREAK）。
- 双方统领均为随从型统领的对局中，主动破城方直接获胜；主动破城具有优先级，以避免双方条件同时满足时产生平局。

## 10. 关于联机与特殊区域

当前版本为单机（人机 / 双人同屏）。联机对战待数值平衡测试充分后再行开发。

规则中的“领域区”是本局内的公开特殊区域，不连接外部网络，也不代表账号云存档或服务器功能。不同阵营可以在领域区中使用各自的子区域和处理方式；同一张卡牌实例在同一时刻只能处于一个区域。

## 11. 数值结算规则

### 11.1 Buff / Debuff 数值范围

- **声明期**：amount 可为负数（保留卡牌设计自由度）。
- **结算期**按数值类型分别处理：

| 数值类型 | 负值处理 |
|---|---|
| HP / 生命值 | 保持负数参与计算；全部伤害结算完成后若仍 < 0 则判定死亡 |
| Attack / 攻击力 | clamp 到 0（攻击不能为负） |
| 持续时间 / 回合数 | clamp 到 0（不存在负持续时间） |
| Cost / 法力费用 | 当前基础规则不启用独立法力系统；若未来启用，负值 clamp 到 0 |
| 其他通用 stat | clamp 到 0 |

amount = 0 仍视为“无意义 buff”并报错（设计意图校验保留）。

### 11.2 统领与效果交互（字段 Flag × 时点二维模型）

统领与非统领来源效果（反制 / 禁用 / 沉默 / 变形等）的交互由两条**正交**轴决定。字段是字段，时点是时点，两者不冲突。

#### A. 字段 Flag 轴（静态：哪一种效果能从统领身上生效）

统领级弱点白名单 vulnerabilities: List<EffectType>：

- **默认空**（= 全免疫）。
- 列出具体效果类型后，只有这些类型能作用到统领。
- 列表与 Java Effects.java 的效果类型对齐；C# 端保持一类效果对应一个 EffectType。

#### B. 时点轴（动态：在什么时间窗口读写这些 Flag）

| 时点 | 触发时机 | Flag 状态变化 |
|---|---|---|
| **降临时刻**（OnEnter） | 统领正面朝上洗入卡组后立即降临 | 按卡牌定义初始化 vulnerabilities |
| **判定时**（OnCheck） | 每个外部效果试图作用统领 | 读取当前 vulnerabilities 决定是否放行 |
| **状态覆写时**（OnMutated） | 卡牌被另一效果改写自身规则 | vulnerabilities 允许被额外或临时修改 |
| **回合结束时**（OnTurnEnd） | 本回合结算结束 | 清除临时覆写，恢复持久 Flag |

Flag 可以在规定时点被读取、写入和恢复；时点不改变 Flag 的类型，Flag 也不规定时点。

#### C. 三步判定链（OnCheck 时点的执行顺序）

当外部效果（Effect）试图作用统领时，按以下顺序校验：

1. **外层门**：Effect.kingSlayer: bool（作用效果类型，不是 leader flag）。
   - false（默认）：该效果不能作用任何统领，直接跳过。
   - true：进入下一步。
2. **效果类型门**：leader.vulnerabilities 是否包含 Effect.type。
   - 不包含：拦截，记录 EffectTypeImmune。
   - 包含：进入下一步。
3. **逻辑字段门**：目标字段 disable_resistance: bool（如未来需要细分到单个字段）。
   - true（默认免疫）：拦截。
   - false：允许作用。

#### D. 示例

- 对统领的伤害反制：kingSlayer=true 且效果类型（如 DAMAGE）列入 vulnerabilities，依次通过第 1、2 步后生效。
- 沉默入场效果：若 Silence 不在 vulnerabilities 列表中，第 2 步拦截，入场效果正常触发。
- 冰冻统领：冰冻类效果通常 kingSlayer=false，第 1 步直接拦截，与 vulnerabilities 无关。

## 12. 阵营机制规范（候选，暂未启用）

本章记录已经统一的设计语言和边界，不表示当前引擎已经支持这些机制。正式启用前，必须补齐卡牌 Schema、运行时状态、合法动作、快照、事件、AI 策略和测试。

### 12.1 领域区的共享语义

- 领域区是不同阵营共享的特殊区域框架，作用类似于独立于手牌、牌库、战场和墓地的指令区；各阵营通过不同子区域体现职业特色。
- **提交队列**与**云端栈**是通用区域框架（2026-08-15 人类确认：云端/领域区所有阵营均可使用，机械为主力使用者；木 owl 等卡也可置入云端）；星位机制以后作为补充包内容使用领域区中的**星图区**，不属于当前基础卡组重做范围。
- 卡牌进入领域区后立即离开原区域，不再同时属于手牌、牌库、战场或墓地。
- 每个子区域必须明确公开性、顺序、合法入口、合法出口和结算时点。机械的两个子区域均公开，双方可以查看卡牌身份与顺序。
- “云端”“Commit”“Push”“Rollback”“Pull”都是游戏内主题术语，不代表真实网络、账号数据、服务器功能或 Git 操作。

### 12.2 木阵营：成长与强化

- 木阵营是慢速成长卡组，通过承担前期压力换取后期爆发性的强化上限。
- 木阵营拥有**扎根（加法蓄力）**与**疯长（乘法倍增）**双计数器（2026-08-15 定稿，替代旧"连乘"）：
  - **扎根 rootStacks（普通 buff·加法）**：打出扎根卡 → 层数 +1；施加强化时按层数增加 buff（强化量 = 基础 + 层数×4），应用后消耗层数。
  - **疯长 rampantStacks（统领 buff·乘法，属特殊扎根）**：wood_leader 提供（正常出场 +1 / 惩罚降临 +2 / 无伤回合 +1，**上限 3 层**）；每施加一个 buff 累乘一次（强化量 ×= 2^层数，持续不消耗）。
  - 乘法由统领体现强大（人类澄清：普通卡 buff 累加、统领效果累乘）。
- 木统领降临（enterEffects）时可以向指定区域加入专用成长卡牌，使统领降临成为后期成长体系的启动点。
- 扎根/疯长强化只能以己方单位或共享王城为目标，不能强化敌方单位。
- 己方单位接受**受扎根/疯长增幅的强化**后进入“封印”状态：攻击力变为 0，不能攻击；其卡面关键词、触发能力、主动能力、被动能力及其他规则文本全部失效。该单位只保留稳定身份、归属、区域、当前生命与生命上限，并仍可受到合法的伤害、恢复、生命强化和破坏。普通 buff（无增幅）不触发封印。
- 王城接受强化时只获得生命强化，不获得木阵营归属、卡牌能力或胜利资格，仍然是双方共享的中立单位。强化王城是木阵营对抗前期破城压力的防御路线，不属于木阵营的巨型单位胜利轴。
- 扎根/疯长进度属于木方玩家或统领的公开成长状态，不附着于接受强化的目标。目标离场、被摧毁或进入墓地，不会重置已经积累的进度；已支付的代价也不返还，但已经施加到该目标上的生命数值随该实例离场而消失。
- 木阵营的候选后期胜利轴，是使一名己方、非统领且处于封印状态的单位达到极高生命阈值。**512 生命**作为当前主题目标进入平衡测试；最终阈值、倍率公式、数值上限、进度消耗方式及胜利检查时点仍需冻结，正式启用前不构成当前对局的胜利条件。王城生命不计入此胜利轴。

### 12.3 海阵营：潮位与潮蚀

- 潮位是附着于玩家的公开状态，不是卡牌的隐藏标记，也不等于累计弃牌数。
- 海卡通过明确效果给对手增加潮位；潮位的增加、衰减、上限和消耗必须由效果或阶段规则明确声明。
- 潮位不得自动计入 OPP_DISCARD_TOTAL_GE，也不得从同一个弃牌事件重复推导出多份资源。
- 海阵营的基本方向是低惩罚值、前期铺场和潮位干扰。潮位奖励不应把所有低惩罚牌进一步降为无风险牌。
- 海卡可以明示消耗对手身上的潮位，施加 DEBUFF、干扰效果，或在对手卡牌计算有效惩罚值时提高该次惩罚，使海方获得额外抽牌并加快触及自身统领。潮位不会在没有卡牌或统领效果声明时自动修改惩罚值。
- **海统领候选：潮汐债务。** 海统领降临时读取对手尚未消耗的潮位；未消耗潮位转化为潮汐债务，使海统领的一项指定参数变弱，随后潮位清除。生命池、降临抽牌、特殊效果和胜利条件中只能选择明确的一项作为削弱对象，不能使用“统领整体变弱”这种未定义表述。
- 在未另行批准前，海的主胜利轴仍是统领定义中的弃牌胜利；潮位不自动成为第二胜利条件。
- 以下内容尚未冻结：潮位上限、来源范围、衰减时点、潮位与有效惩罚值的交换比例和响应窗口、潮汐债务的具体参数、弃牌胜利阈值以及对手的退潮手段。

### 12.4 机械阵营：提交（Commit）/ 上传（Push）/ 回滚（Rollback）/ 下载（Pull）

以下名称是游戏内动作，不代表 Git 操作（中文术语 = 卡面标准用语，2026-08-15 词表定稿）：

- **提交（Commit）**：玩家选择一张合法机械卡并支付该卡声明的提交惩罚费用；支付成功后，该卡立即离开原区域，进入己方公开的提交队列。普通提交以己方场上机械卡为来源；卡牌效果可以明确指定其他来源，例如牌库顶牌。
- 提交使用现有惩罚值框架，不启用独立法力资源。除非效果明确写明免除费用，由效果发起的提交仍支付被提交卡的提交惩罚费用。
- 提交队列是独立区域。队列中的卡牌已经离场，不能攻击、发动主动能力，也不能被仅以手牌、战场、牌库或墓地为目标的效果选中。
- **回滚（Rollback）**：选择己方提交队列中的一张合法卡牌，将其移回手牌。回滚不返还已经支付的提交费用，不触发上传或下载效果，也不能回溯已经发生的抽牌、伤害、随机结果或事件记录。
- **上传（Push）**：上传不是玩家主动按钮，而是结束阶段的自动结算步骤。当前玩家的其他结束阶段效果全部处理完毕后，引擎才按提交顺序从队首开始逐张处理提交队列。
- 每张卡进入云端栈的一瞬间触发自身明确声明的上传效果。若该效果需要目标，引擎在该牌实际上传时暂停结束阶段，并依据当时的权威状态生成目标选择子步骤；目标由当前玩家在此时选择，不能在 Commit 时预选，也不能由客户端自行推导。
- 最早提交的牌最先上传；后上传的牌压在已有牌之上，因此最后提交的牌最终位于栈顶。一个需要选择目标的上传完整结算后，才继续处理队列中的下一张牌。
- 上传结算过程中产生的新提交不加入当前处理批次，而是保留到相应玩家下一次结束阶段。全部上传处理完后才进行最终胜负检查；若对局尚未结束，才把回合交给下一名玩家。
- **下载（Pull）**：只能选择己方云端栈顶卡牌，不能跳过栈顶访问下层。玩家支付该牌声明的下载惩罚费用后，将其从云端移出，结算其下载效果，随后把该牌移入墓地；若栈顶当前不能合法下载，则本次下载不可执行。
- 机械统领正式降临后，本局己方下载（Pull）的有效惩罚费用变为 0。该效果只免除下载费用，不影响普通出牌惩罚、提交费用或上传时点。
- 提交队列和云端栈不设置“容量 3”或“每回合只能上传／下载一次”之类的基础限制；具体卡牌可以自行声明限制，引擎仍须防止同一卡牌实例被重复结算。
- 机械随从的重设计基线是普通出牌惩罚值为 0、基础身材偏低，再通过提交、上传、回滚与下载形成转换收益；具体身材和单卡效果由卡牌数据与平衡测试确定。
- **协议字段**是机械统领用于读取构筑进度的标准化能力标识，可以来自机械动作、关键词或效果时点，例如 COMMIT、PUSH、ROLLBACK、PULL、CHARGE（冲锋）、STEALTH（潜行）、TAUNT（嘲讽）、BATTLECRY（战吼）、DEATHRATTLE（亡语）。相同字段无论由多少张牌提供，在同一次集合判定中只计一次。
- 每名机械统领必须在自身定义中明确声明可计入的协议字段白名单、所需组合或数量，以及胜利检查时点。以后新增的协议字段不会自动计入旧统领的胜利条件；只有对应统领定义明确纳入后才生效，从而避免字段池扩张导致旧胜利条件自然贬值。
- machine_alpha 的胜利条件确定为**下载轴（Pull）**：通过累计下载（Pull）达成特定条件即获胜，与惩罚抽卡无关（替换现有 OPP_PUNISH_DRAW_TURN_GE，2026-08-15 人类裁决）。具体协议组合与阈值交 QA/策划定稿（统领重设计批次）；在新定义完成数据、引擎与测试接入前，当前运行时继续使用原值。

#### 12.4.1 规范化示例

    降临：将己方牌库最上方的卡牌提交。

    结算：公开牌库顶牌并支付其提交惩罚费用，
    然后将其移入提交队列；它不会立即触发上传。

    回合结束：其他结束阶段效果全部处理后，
    该牌按队列顺序进入云端并触发自身上传效果。

这只是字段语义示例，不代表当前卡牌数据已经加入该牌。

### 13.5 惩罚机制 v2（2026-08-15 人类定稿）

- **触发**：卡被惩罚抽到（对方喂牌）时，**立即可用**——支付惩罚降临费用后打出。
- **结算顺序**：触发普通效果（降临/本卡效果）→ **追加惩罚效果**。
- **惩罚降临值**（punishCost）：被惩罚抽到使用时的**替代费用**（替代打印惩罚值）；可低于/等于打印值；**也可仅降低费用而无额外惩罚效果**（如 growth 惩罚降临 0 = 被喂时 0 费使用，无追加）。
- **伏击卡不设惩罚效果**（盖放触发机制与惩罚追加冲突）。
- **"变更为"语义（2026-08-15 冻结）**：普通卡惩罚 = **追加**（方案 B：普通效果 + 追加惩罚效果均结算）；**"变更为"卡惩罚 = 替换**（方案 A：惩罚触发时普通效果被变体**替换**，只结算变体，不追加）。两类卡并存，语义分离。
- **超模容忍**：每阵营允许 1-2 张超模卡（2026-08-15 人类确认），以阵营特色/胜利轴补偿。
