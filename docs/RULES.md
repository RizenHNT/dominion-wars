# 《统御战纪》规则书（v1.0）

本规则书是当前引擎实现的权威描述，包含开发过程中确定的全部裁决。
所有数值默认值均可在 `data/balance.json` 中调整。

## 1. 对局目标

**唯一核心胜利方式：击败对方统领。**

- 在双方统领都登场之前，对局不可能分出胜负（门限保护：任何会致负的数值在此期间最低钳制为 1）。
- 唯一例外：**洗牌判负** —— 一方累计洗牌达到上限（默认 10 次）立即落败。
- 统领可附带**特殊胜利条件**（见 §7），达成同样视为击败对方统领。

## 2. 卡牌类型

| 类型 | 说明 |
|------|------|
| 随从 | 具有攻击力/生命值，登场后可参与战斗 |
| 咒文 | 打出立即结算；可带【吟唱 X】：先入场等待 X 回合后才结算 |
| 伏击 | 伏击阶段盖放，对方执行特定动作时触发 |
| 惩罚牌 | **无法主动打出**。只能在对方回合被惩罚抽到且满足条件时发动，效果强力；若以非惩罚途径抽到，本回合结束阶段自动销毁 |

任何类型的卡都可以附带【惩罚】字段（`punishActivatable`），获得"被惩罚抽到时可发动"的能力。

## 3. 惩罚值系统（核心机制）

- 每张卡都有**惩罚值**。你打出卡牌时，**对方立即抽取等量的牌**。
- 对方因此抽到带【惩罚】的卡且满足其附加条件时，可立刻以**降低后的惩罚值**（`punishCost`）发动它——这会反过来使你抽牌，可能形成**连锁**。
- 连锁允许无限进行，引擎设硬上限 20 层防止死循环；卡牌设计上通过限制响应面来克制。
- 发动惩罚效果前，还须校验该卡惩罚以外的其他条件（如"敌方随从≥2"）。

### 3.1 空发裁决

- 若你打出卡牌时其惩罚值 **大于** 对方卡组剩余张数：允许打出，但该牌**空发**——计为使用、消耗词条、效果不结算、对方不抽牌，并且你**强制进入弃牌阶段结束回合**。
- 惩罚值**恰好等于**对方卡组余量：合法，正常结算抽空对方卡组；之后你仍可继续打出惩罚值为 0 的卡。
- **对方回合中**因惩罚发动造成的空发，不会结束任何人的回合。
- 对方卡组无牌时，对局进入"强制结束当前回合"状态。

### 3.2 先驱威压

当**仅一方**统领在场时：

- 对方所有卡牌惩罚值 **+1**（`pioneerOpponentPunishBonus`，默认 1）；
- 统领方弃牌上限 **+2**（`pioneerHandLimitBonus`）；
- 备选配置：统领方自己的卡牌惩罚值 **−N**（`pioneerSelfPunishDiscount`，默认 0）。

设计意图：让先打出统领成为明确收益，避免双方互相憋统领拖慢节奏。

## 4. 词条限制

- 每张卡可带若干**词条**（如"破坏""弃牌""恢复"）。
- **同一玩家的同一词条，每个"回合段"只能使用一次。**"回合段"指两次玩家交替之间的全部时间——每当回合从一名玩家转移到另一名玩家时，**双方**的词条使用记录全部重置。
- 伏击牌的词条在**触发时**消耗（盖放不消耗）；惩罚值则在**盖放时**支付。

## 5. 回合结构

```
开始阶段（抽牌；卡组空则洗牌） → 伏击阶段（可盖放） → 行动阶段（出牌/攻击）
  → 弃牌阶段（超过上限须弃至上限） → 结束阶段（吟唱推进、惩罚牌销毁等） → 交替
```

默认数值：起手 5 张，每回合抽 1 张，后手第一个回合额外 +1 张，手牌上限 8，卡组 60–80 张（含统领恰好 1 张）。

- 弃牌阶段的**强制弃牌不计入**"对方累计弃牌"类胜利条件；只有效果造成的弃牌与惩罚转化弃牌计入（防止挂机自动达成）。

## 6. 伏击

- 每回合**限盖放 1 张**；每个敌方动作**最多触发 1 张**伏击响应。
- 三种类型：
  - **普通**：可在伏击区累积多张；
  - **专注**：触发的回合压制你其他所有伏击（不可再触发）；
  - **封场**：盖放期间你不能再盖放其他伏击。

## 7. 统领牌

- 每卡组**必含 1 张**统领，开局**正面朝上**洗入卡组。
- 任何手段（含被惩罚）抽到统领，**立即自动登场**：随从统领进战场，非随从统领进统领区（伏击统领进伏击区）。
- **被惩罚抽到**统领会额外触发其**强力惩罚效果**。
- 统领**永不离场**：摧毁/退场/变形等效果对统领一律**空发**；唯一例外是统领自身效果使其离场（如伏击统领触发后洗回卡组）。
- 统领能力按字段拆分（`win_condition` / `entrance_effect` / `passive_effect` / `activated_ability`），详见 §11.2.
- 统领的存在形式（由其定义决定）：
  - 随从统领：以攻/血战斗，生命归零被击败；
  - 耐久统领：自身耐久归零被击败；
  - 赋予生命统领：给予玩家生命值，归零则该方落败。
- 统领可附带特殊胜利条件，例如：
  - `OPP_DISCARD_TOTAL_GE n`：对方累计（受效果）弃牌 ≥ n；
  - `NO_DAMAGE_TURNS_GE n`：己方连续 n 个回合未受任何伤害；
  - `OPP_PUNISH_DRAW_TURN_GE n`：对方单回合内因惩罚抽牌 ≥ n 张。

## 8. 战斗

- 随从每回合可攻击次数为卡牌字段（默认 1）。
- 召唤当回合不可攻击（**突袭**除外）。
- 关键词：
  - **突袭**：召唤当回合即可攻击；
  - **嘲讽**：对方必须优先攻击嘲讽随从；
  - **圣盾**：抵消受到的第一次伤害；
  - **扰魔**：不能成为咒文/惩罚效果的目标；
  - **永续**：标记型关键词，配合永续光环类效果。

## 9. 牌库循环与胜利计数

- 开始阶段卡组为空时，将墓地洗回卡组（可配置是否包含手牌），称为一次有效牌库循环。
- 某玩家发生有效牌库循环时，其对手的胜利计数 +1。
- 一方胜利计数达到上限（默认 10）即获胜。
- 个别效果（如机械阵营）可使“下一次牌库循环不增加对手胜利计数”。
- 王城被击破时，破城方自己的胜利计数设为至少 9。

## 10. 关于联机

当前版本为单机（人机 / 双人同屏）。联机对战待数值平衡测试充分后再行开发。

## 11. 数值结算规则

### 11.1 Buff / Debuff 数值范围

- **声明期**：`amount` 可为负数（保留卡牌设计自由度）。
- **结算期**按数值类型分别处理：

| 数值类型 | 负值处理 |
|---|---|
| HP / 生命值 | 保持负数参与计算；全部伤害结算完成后若仍 < 0 则判定死亡 |
| Attack / 攻击力 | clamp 到 0（攻击不能为负） |
| 持续时间 / 回合数 | clamp 到 0（不存在负持续时间） |
| Cost / 法力费用 | clamp 到 0（最多免费，不存在负费用） |
| 其他通用 stat | clamp 到 0 |

`amount = 0` 仍视为"无意义 buff"并报错（设计意图校验保留）。

### 11.2 统领与效果交互（字段 Flag × 时点 二维模型）

统领与"非统领来源"效果（反制 / 禁用 / 沉默 / 变形等）的交互由两条**正交**轴决定。**字段是字段、时点是时点**，两者不冲突。

#### A. 字段 Flag 轴（静态 — 哪一种效果能从统领身上生效）

统领级弱点白名单 ulnerabilities: List<EffectType>：

- **默认空**（= 全免疫）。
- 列出具体效果类型 → 那些类型**能**作用到统领。
- 列表与 Java Effects.java 24 个 case 对齐（C# 端 1 IEffect = 1 EffectType 取值）。

#### B. 时点轴（动态 — 在什么时间窗口读 / 写这些 Flag）

| 时点 | 触发时机 | Flag 状态变化 |
|---|---|---|
| **登场时** (OnEnter) | 统领正面朝上洗入卡组后立即登场 | 初始化：按卡牌定义锁定 ulnerabilities 初值 |
| **判定时** (OnCheck) | 每个外部效果试图作用统领 | 读当前 ulnerabilities 决定是否放行 |
| **状态覆写时** (OnMutated) | 卡牌被另一效果改写自身规则 | ulnerabilities 允许被额外 / 临时修改 |
| **回合结束时** (OnTurnEnd) | 本回合结算结束 | 清临时覆写，恢复"持久 Flag" |

Flag 在时点上被读、被写、被恢复；时点不改变 Flag 的类型，Flag 也不规定时点。

#### C. 三步判定链（OnCheck 时点的执行顺序）

当外部效果（ffect）试图作用统领时，按以下顺序校验：

1. **外层门** — ffect.kingSlayer: bool（**作用效果类型**，不是 leader flag）
   - alse（默认）：该效果**不能**作用任何统领，直接跳过。
   - 	rue：放行。
2. **效果类型门** — leader.vulnerabilities 是否包含 ffect.type
   - 不在：拦截，日志 EffectTypeImmune。
   - 在：放行。
3. **逻辑字段门** — 目标字段 disable_resistance: bool（如未来需要细粒度到 4 字段）
   - 	rue（默认免疫）/ alse（可被作用）。

#### D. 示例

- shadow_of_fate 反制：kingSlayer=	rue 且 effects 配置在 vulnerabilities → 第 1 步放行、第 2 步放行 → 生效。
- "沉默入场效果"：若 Silence 不在 vulnerabilities 列表 → 第 2 步拦截，入场效果正常触发。
- "冰冻统领"：冰冻类效果通常 kingSlayer=false → 第 1 步直接拦截，与 vulnerabilities 无关。
