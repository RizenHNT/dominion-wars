## 三、设计工具链（v2 使用）

1. **风险定价凸函数**：Budget_A(P) = 4.55 + 0.25P + 0.16P²（高 P 卡 mill/终结双收益）
2. **双费用系统**：P（自己回合）+ P'（惩罚降临费，被喂时）——表 A/表 B 分离
3. **连锁控制**：惩罚组件 ≤25%、响应率 20-30%
4. **Skinner 配额**：卡池全合规；超模卡在构筑层体现（60 张卡组放 6-9 张，见设计模型 §13.3），不在 540 张卡池数据里标字段
5. **特点权重**：服务胜利轴的特点允许溢价（火破城/木成长 +0.5~2）
6. **费用曲线**：按节奏档定制（火偏前期低费、木 0 基干+高费终结）

## 四、数据结构

JSON 字段（对齐 data/schema/cards.schema.json）：
- id = 语义词根（flame_imp 式，前缀 flame/machine/sea/wood/neutral_）
- name = 中文卡名（0 重复）
- faction = 阵营枚举（5）
- type = MINION / SPELL / AMBUSH / PUNISH（英文枚举）
- punish = 打印惩罚值 P（自己回合费用）
- punishCost = 惩罚降临费用 P'（被喂时）
- attack / health = 数字身材（MINION）
- keywords = 关键词数组
- onPlayEffects / punishEffects / ambushEffects = EffectSpec 数组（对齐 schema $defs）
- tags = 主题归属
- text = 面向玩家展示文本
- leader + leaderDef = 统领结构化（winCondition / enterEffects / punishEffects）
