# Dominion Wars v1.0 → Castle Prototype 修改记录与设计反馈

> 本文档用于记录《统御战纪 / Dominion Wars》从 v1.0 原始版本到当前王城原型分支的规则实验、UI 调整、AI 调整、测试结果与遗留问题。  
> 当前修改均为原型验证性质，后续正式实现建议由 Claude 按原项目代码风格统一重写。

---

## 0. v1.0 原始版本概况

### 核心机制

v1.0 的核心机制是“惩罚值”。玩家打出卡牌时，不消耗传统费用，而是让对手按该牌惩罚值抽牌。对手因惩罚抽到特定卡牌时，可以触发惩罚效果并形成连锁。

这个机制本身成立，能制造“我越展开，对手越可能反击”的风险感。

### 原始阵营定位

- **烈焰帝国**：速攻、直伤、铺场、强压。
- **深海联盟**：弃牌、控制、特殊胜利。
- **古木圣地**：防御、恢复、无伤特殊胜利。
- **机械遗迹**：吟唱、协议、惩罚抽牌特殊胜利。

### v1.0 暴露的核心问题

1. **统领未登场时，很多卡牌没有价值。**  
   烈焰的火舌小鬼、飞火流星、狂热战士等“对敌方统领造成伤害”的卡，在敌方统领未登场时会直接落空。

2. **统领形态不统一。**  
   原始统领有随从型、咒文型、生命型、耐久型、伏击型等多种形态，但卡牌文本经常统一写“敌方统领”，导致承伤逻辑不稳定。

3. **随从型统领风险过高。**  
   烈焰皇·焚天像普通大随从一样被攻击、被反伤、被效果处理，而深海、古木、机械统领更像规则装置。烈焰皇承担了更多风险，却没有足够的统领级保护。

4. **特殊胜利被统领未齐卡住。**  
   原版中会出现“特殊胜利条件达成，但双方统领未齐——游戏尚不能结束”的日志。玩家完成胜利任务却不能赢，体验不自然。

5. **墓地洗回卡组时状态没有重置。**  
   长局中可能出现 0 血或负血随从被重新抽到。该问题已在原型中修复：墓地/手牌洗回卡组前重置运行时状态。

## 1. Castle Prototype v1：共享王城

### 新增系统：共享王城

加入一个中立公共目标：**王城**。

王城不是双方各自的护盾，而是一条双方共享的公共血条。双方都可以攻击王城。谁造成最后一击，谁成为破城方。

### 设计目的

- 让统领未登场时仍有可攻击目标。
- 让“对统领伤害”不再落空。
- 通过共享血条制造抢最后一击的博弈。
- 让解场更有价值：如果自己把王城打残却不解场，对手可能偷最后一击。

### 初版规则

- 王城初始血量：60。
- 原本指向敌方统领或敌方核心的伤害，在王城存在时优先打王城。
- 王城被击破时：
  - 破城方的对手首领被强制出场；
  - 不视为抽到，不触发惩罚；
  - 登场效果暂时正常触发；
  - 原型中曾将受害者洗牌计数设为至少 9，后续已改为“破城方胜利计数设为至少 9”。

### 测试结论

王城机制有效解决了“打统领伤害落空”的问题。烈焰前期终于能推进目标。

问题是 v1 将所有核心伤害强制导向王城，玩家和 AI 无法选择打王城还是打已登场统领。

## 2. Castle Prototype v2：王城 75 与烈焰破城胜利

### 王城血量调整

测试过 60、75、100。

当前结论：

- 60：偏快，烈焰容易过早破城。
- 75：比较合理。王城会被打破，但不是每局都会破。
- 100：过厚，烈焰破城次数下降，直伤又容易变成沉没成本。

当前推荐：**王城血量暂定 75**。

### 烈焰破城胜利

为烈焰皇·焚天加入胜利方向：

- 烈焰方击破王城时，直接获胜。
- 该胜利不受“双统领必须都在场”的门限保护。

设计目的：强化烈焰“攻城速攻”身份，让烈焰直伤和铺场有明确战略目标。

### v2 主要结果

1200 局模拟中：

- 原版无王城：烈焰 60.8%，机械 48.7%，深海 47.0%，古木 43.5%。
- 王城 75 + 烈焰破城胜利：烈焰 50.5%，机械 57.7%，深海 43.3%，古木 48.5%。
- 王城 100：烈焰 47.0%，机械 59.0%，深海 45.0%，古木 49.0%。

结论：王城 75 是当前卡池下较好的测试基准。

## 3. Castle Prototype v3：AI 改进与伤害类型拆分

### AI 改进方向

v3 尝试让 AI 理解王城机制：

- 王城可被击破时，优先抢破城。
- 王城低血时，优先解场，防止对手补刀。
- 面对古木快达成无伤胜利时，优先断计数。
- 不再无脑把所有核心伤害砸向王城。

### 伤害类型拆分

将伤害分为：

1. **群体伤害**：只按群体结算，不会乱打王城或统领。
2. **可选目标单体伤害**：可在合法目标中选择敌方随从、王城、已登场统领、生命型统领等。

### v3 主要结果

1200 局模拟：

- 烈焰：42.5%
- 机械：63.7%
- 深海：42.3%
- 古木：51.5%

v3 规则结构比 v2 正确，但暴露出烈焰皇缺少统领抗性的问题：单体伤害能选择目标后，烈焰皇更容易被直接处理。

## 4. Castle Prototype v4：护卫、弑君、统领抗性

### 新字段：护卫 guard

随从型统领拥有护卫时，只要己方场上存在其他非统领随从，敌方不能攻击该统领。

当前添加护卫的统领：

- 烈焰皇·焚天
- 上古极神 Alpha
- 命运之影

### 新字段：弑君 kingSlayer

默认情况下，敌方普通卡牌效果不能影响统领。拥有弑君的卡可以绕过统领抗性，对统领生效。

当前代表性弑君卡：

- 烈焰：火焰冲击
- 深海：深压猛击
- 古木：月华射线
- 机械：轨道炮

### 统领默认抗性

统领不再像普通随从一样吃敌方普通效果。普通单体伤害、指定破坏、普通群伤等不能随意影响敌方统领。友方治疗、增益仍可作用于己方统领。

### 机械机身补耐久

机械初始统领“上古咒文·赋值机身”补充耐久 8，避免“攻击成功但没有可损耗字段”的问题。

### 特殊胜利强制统领现身

王城规则启用时，如果特殊胜利条件达成，但对方统领未登场，则强制未登场统领现身，再结算胜利。

### v4 主要结果

2400 局 AI 模拟：

- 平均回合数：14.46
- 最长对局：29 个玩家回合
- 未完成对局：0
- 100 回合以上：0

胜率：

- 烈焰：43.5%
- 机械：61.8%
- 深海：32.4%
- 古木：62.3%

规则制约改善：

- 非法攻击目标：大量出现 → 0
- 无可损耗字段：大量出现 → 0
- 特殊胜利被统领未齐卡住：大量出现 → 0

v4 的主要问题转向阵营平衡：古木、机械偏强，深海偏弱，烈焰仍需要更好的破城 AI。

## 5. 当前新增修改：项目文档、UI、胜利计数语义

### 5.1 新增本文档

新增：

- `docs/CHANGELOG_CASTLE.md`

用于记录 v1.0 到王城原型分支的设计变更、测试结论与遗留问题。

### 5.2 UI 可读性调整

当前 Swing 对战界面存在问题：

- 伏击区只能看到数量，看不到自己盖了什么。
- 手牌太多时一行挤爆，后续手牌不可见。
- 战场和手牌没有足够滚动区域。
- 页面整体缺少层次感。

原型中已做以下调整：

- 新增对方伏击区与己方伏击区显示。
- 己方伏击显示真实卡名和伏击类型。
- 对方伏击在人类视角下隐藏内容，只显示“伏击 1 / 已盖放”。
- AI 对 AI 观战时可显示伏击内容。
- 手牌区改为多列网格，并放入滚动面板，手牌过多时可向下滚动查看。
- 战场区改为网格，并放入滚动面板。
- 调整窗口尺寸、日志字体、阶段栏颜色与背景，使信息层次更清楚。

该 UI 仍是可用性修补，不是最终美术方案。

### 5.3 洗牌计数改为胜利计数

原 v4 处理是：王城被击破时，将被破城方的洗牌计数设为至少 9。

该语义存在问题：

- 看起来像是给对方一个“失败计数”。
- 破城后容易让对手进入一种诡异的“被逼到 9 但还能继续利用大量抽牌/循环”的状态表达。
- UI 上不够直观：玩家应该看到的是“我离胜利还差多少”，而不是“对方离失败还差多少”。

当前修改为：

- 每名玩家拥有自己的“胜利计数”。
- 当某玩家发生有效牌库循环时，其对手的胜利计数 +1。
- 胜利计数达到阈值 10 时，该玩家获胜。
- 王城被击破时，破城方自己的胜利计数设为至少 9。
- 机械“洗牌免计数”改为：本次牌库循环不增加对手的胜利计数。

等价理解：

- 不是“我洗牌 10 次我输”；
- 而是“对手的牌库循环 10 次，我赢”。

王城击破后：

- 破城方胜利计数变为至少 9；
- 之后只要对手再发生一次有效牌库循环，破城方就获胜。

这样更符合“破城方获得终局优势”的直觉，也更适合 UI 表达。

## 6. 当前主要未解决问题

### 6.1 深海过弱

深海有弃牌，但弃牌后缺少联动收益。

建议新增：

- `onDiscard`：被弃置时触发。
- `onOpponentDiscard`：对方弃牌时触发。
- 潮汐计数：弃牌转化为深海资源。
- 深海反抢王城工具。
- 深海低血王城补刀工具。

### 6.2 古木过强

王城受伤目前不一定打断古木无伤计数，导致古木在对手争王城时容易偷偷完成特殊胜利。

可考虑：

- 王城受到敌方造成的伤害时，打断古木无伤计数。
- 无伤胜利从 4 回合改成 5 回合。
- 无伤计数只在世界树登场后开始。

### 6.3 机械过强

机械特殊胜利触发频率较高。

可考虑：

- Alpha 特殊胜利阈值从 8 调整到 9 或 10。
- 特殊胜利只统计 Alpha 登场后的惩罚抽牌。
- 调整机械统领惩罚加值。

### 6.4 烈焰仍需 AI 优化

烈焰有破城胜利，但仍需要更精确的 AI：

- 王城低血时保留直伤补刀。
- 不把公共王城打残后送给对手。
- 有护卫时保持随从保护烈焰皇。
- 选择解场还是抢城时更看重对方下回合伤害。

## 7. 推荐正式重写基线

建议 Claude 正式重写时以当前原型为设计基线，但不要机械照搬原型代码。

推荐保留：

- 王城血量 75。
- 共享王城。
- 烈焰破城即胜。
- 统领默认抗性。
- 护卫 guard。
- 弑君 kingSlayer。
- 单体伤害与群体伤害分离。
- 机械机身耐久。
- 特殊胜利不再被统领未登场卡死。
- 墓地洗回卡组时重置卡牌运行时状态。
- 胜利计数语义：对手循环给我胜利计数，破城方胜利计数设为至少 9。

不推荐：

- 王城降到 40/45。
- 王城升到 100。
- 所有伤害强制打王城。
- 统领像普通随从一样吃所有效果。
- 普通全场解直接破坏统领。
- 使用 320、750、1250 等复杂中间数值。

## 8. 总结

v1.0 的惩罚机制有潜力，但统领系统没有统一建模，导致前期大量卡牌空转。共享王城解决了“没有目标可打”的问题，并引入公共目标、抢最后一击、控血线与解场博弈。

当前原型已经把主要规则地基补齐：

- 王城负责前中期公共争夺。
- 统领负责核心胜负。
- 护卫保护随从型统领。
- 弑君提供反统领例外。
- 单体伤害和群伤边界更清楚。
- 胜利计数语义比原本“洗牌判负计数”更直观。

下一阶段重点应是：

1. Claude 按原代码风格重写规则层；
2. 正式整理 UI 布局；
3. 重做深海弃牌联动；
4. 调整古木、机械特殊胜利；
5. 优化 AI 对王城、护卫、弑君、补刀的判断；
6. 重新进行大规模模拟测试。

## 13. Castle Prototype v6：操作层 UI/UX 修补

### 13.1 当前阶段可用 / 不可用牌区分

Swing 对战界面的手牌现在会根据当前阶段显示可用状态：

- 伏击阶段：只有可以盖放的伏击牌显示为可用；其他牌显示为不可用。
- 行动阶段：只有可以主动打出的牌显示为可用；伏击牌、未激活惩罚牌、词条受限牌等显示为不可用。
- 非当前玩家或非操作阶段：手牌整体不可用。

可用牌使用更明显的边框与状态文字，避免玩家必须逐张点击或查看 tooltip 才知道当前能做什么。

### 13.2 伏击阶段自动推进

如果人类玩家进入伏击阶段后已经没有任何可执行伏击操作，界面会自动进入行动阶段。

典型情况：

- 手牌中没有伏击牌；
- 已经盖放过一张伏击；
- 封场伏击导致无法继续盖放；
- 伏击牌由于规则限制无法盖放。

该改动用于减少“盖完伏击后还要手动点跳过伏击阶段”的无意义操作。

### 13.3 卡牌小组件信息拆分

卡牌按钮不再只显示卡名和一行文字，而是拆成更接近卡牌小组件的信息结构：

- 右上角显示惩罚值 P；
- 类型使用图标与颜色区分：随从 / 咒文 / 伏击 / 惩罚；
- 随从显示攻击 / 生命；
- 非随从统领显示耐久；
- 吟唱牌显示吟唱回合；
- 护卫、弑君等关键字段直接显示在牌面；
- 可用、不可用、可攻击、可选目标等状态直接显示。

设计目标：让玩家通过牌面颜色、图标和数字直接判断基本信息，而不是逐张阅读完整文字。

### 13.4 战场与手牌滚动改善

- 手牌区高度增加；
- 手牌和战场改为更多列的网格布局；
- 滚动速度提高；
- 战场单位在可攻击时显示绿色边框；
- 选择攻击者后，合法攻击目标显示红色边框。

### 13.5 后续 UI 建议

当前 v6 仍然只是“功能性美化”，还不是最终卡牌 UI。

后续建议：

1. 将 JButton 牌面替换为专用 CardPanel；
2. 使用固定卡牌尺寸和更清晰的版式；
3. 增加卡牌悬浮大图；
4. 增加手牌分页或横向滚动；
5. 伏击区使用背面卡牌样式；
6. 王城、统领、胜利计数使用独立 HUD，而不是混在文字信息条中；
7. 用颜色主题区分阵营。

## 13. Castle Prototype v7：设置、显示模式与多语言 UI 原型

### 13.1 新增设置入口

在主菜单和对战窗口加入“设置”入口。

当前可调整项目：

- 语言：中文 / 日本語 / English
- 页面显示：紧凑 / 标准 / 宽松
- 是否显示卡牌提示 tooltip
- 是否显示对方伏击数量

设置会保存到用户目录下的 `.dominion-wars-ui.properties`。

### 13.2 新增轻量多语言系统

新增：

- `UiSettings`
- `SettingsDialog`
- `I18n`

当前多语言覆盖范围：

- 主菜单按钮
- 设置窗口
- 对战窗口主要区域标题
- 阶段名
- 卡牌类型名
- 伏击类型名
- 操作按钮
- 常见提示弹窗
- 手牌可用 / 不可用状态
- 基础 tooltip 结构

暂未覆盖：

- 卡牌名称
- 卡牌描述
- 阵营名
- 对局日志中的引擎文本
- 编辑器全部字段
- 控制台模式全部文本

原因：这些文本目前直接来自 JSON 或 engine log。后续如需完整多语言，应把卡牌数据和日志消息也拆成 key-based localization。

### 13.3 页面显示模式

页面显示提供三档：

- 紧凑：更多列，卡牌更小
- 标准：默认显示
- 宽松：卡牌更大，列数更少

当前影响：

- 手牌牌面大小
- 战场牌面大小
- 手牌 / 战场网格列数
- 全局 UI 字体大小初始值

### 5.4 数值结算规则与统领 × 效果交互模型（2026-08-12）

本节对应 docs/RULES.md §11.1 - §11.2，由人类项目负责人 2026-08-12 18:28 拍板、PL（MiniMax M3）在 19:15-19:22 落地的设计变更。

**§11.1 Buff / Debuff 数值范围（Decision B）**

- 允许 mount 为负数（Hearthstone 风格）。
- 结算期按数值类型分别处理：HP 保持负数（全部结算后判定死亡）；Attack / Duration / Cost / 其他 stat clamp 到 0。
- mount = 0 仍视为"无意义 buff"报错。

**§11.2 统领 × 效果交互（Decision A，字段 Flag × 时点 二维模型）**

- **字段 Flag 轴（静态）**：统领级弱点白名单 ulnerabilities: List<EffectType>（默认空 = 全免疫），与 Java Effects.java 24 个 case 一一对齐。
- **时点轴（动态）**：4 个判定区间 — OnEnter 初始化、OnCheck 校验生效、OnMutated 改写 Flag、OnTurnEnd 清临时。
- **三步校验链**：effect.kingSlayer → vulnerabilities 含 effect.type → （可选）4 字段 disable_resistance。
- 替代了此前的纯 "4 字段 disable_resistance" 单一机制（爆字段风险 + 与现场时点语义混淆）。

**Impact**

- src/main/java/.../Effects.java 24 个 case → C# IEffect 顺序不变，但 CardDefinition.cs / CardDef.java 等数据结构需要从 Card 层级下沉为 Effect 层级（见 IMPLEMENTATION_TODO.csv L18 "kingSlayer migrate card-level → effect-level"，PL 2026-08-12 已加 P0）。
- 4 张现有 kingSlayer 卡（flame / wood / sea / machine）需要从 card-level 迁移到 effect-level（PL 2026-08-12 19:25 启动指令）。
