# 古木卡牌设计与调整方向审查 — 2026-10-04

审查人：Codex。性质：只读审查、局部机制复现和设计建议；不是最终规则或平衡决定。

补充：本报告描述的是当时的探针。后续共享驱动修复、条件校验和新测量证据见 [模拟驱动修复报告](CODEX_PROBE_DRIVER_REPAIR_2026-10-04.md)。费用、封印等设计假设的复现结论仍适用；旧探针的策略和统计限制不应再当作新驱动现状。

## 结论

**值得保留设计目标，但当前方案不能按报告中的描述交付，最新“动态费用”实验也没有测到预期折扣。**

初始反馈、失去载体后的重建、高费牌承担不同职责、快铺与厚养形成取舍，都是有价值的方向。但若干构筑路线建立在错误的结算假设上，尚未证明它们实际提供了不同的选择。现有证据支持“费用可能过度影响节奏，值得继续检验”，不支持“卡牌设计无关紧要”“唯一瓶颈是经济结构”或“每加 1 点惩罚必定少约 30 个百分点胜率”。

建议先修正设计与结算的对应关系及实验口径，再做小规模原型对比；暂不据此整体下调高费牌或改写费用规则。

## 1. 当前必须先解决的问题

### 1.1 动态折扣没有实现预期收益，部分卡还误称能降低自己的费用

证据：`src/Engine/Effects/EffectRuntime.State.cs` 的 `ApplyPunishDelta`；`src/Engine/Turns/CardPlayRules.cs` 的 `EffectivePunish`；`PlayCardActionHandler.cs` 的费用准备顺序。

回合修正值使用 `after = Math.Max(0, before + amount)`。从 0 加 −2 仍是 0，不能产生低于基础费用的折扣；若原先有 +5 附加惩罚，−2 可以将它减至 +3。这是**移除既有附加惩罚**，并非方案所说的通用费用引擎。先驱威压的修正另行计算，从 0 给负值也不会把它抵消。

复现：加载真实 v2 候选 `wood_v2_bark_token`、`wood_v2_root_tithe`，打出效果前后，下一张基础惩罚 6 的牌都仍需 6，回合修正值仍为 0。

此外，本卡费用先准备，随后才执行登场效果。即使将来允许回合值为负，登场时的 −4 也不能把**已经支付的本卡**从 6 变成 2。v1 的“万木归寂”“深根裂城”仍作了这种描述，和报告自己列出的 B3 边界矛盾。

v2 把条件移到费用效果上，确实改善了对照变量的定义，但它未解决这个底层前提。因此当前两池接近，不是动态费用思路无效的证据。

**处置建议：**当前规则内把此类牌明确设计为“解除加税”的对抗牌；若希望实现通用连出折扣或本卡按局面减费，先提出独立规则方案，明确计算时点、最低费用、次数与反制窗口，再由 owner 决定。不能把放开负值当作普通修 bug 顺手改掉。

### 1.2 厚养的圣盾保护、突袭后封印、只加血不封印，均与实际结算不符

证据：`EffectRuntime.Combat.cs` 的 `Buff`；`CardInstance.cs` 的关键词判断；`EffectRuntime.Attack.cs` 的伤害处理；当前 `docs/RULES.md` 古木封印语义。

| 方案中的设想 | 实际复现 | 对设计的影响 |
|---|---|---|
| `wood_layered_bark` 强化后给封印载体圣盾，用于厚养保护 | 原始 Shield 标记可为 true，但封印后关键词无效；3 点伤害仍完整扣掉 3 血 | 标记存在不能算作有效保护，厚养路线的抗解能力被高估 |
| `wood_rootcutter` 先突袭再靠登场强化封印 | 扎根 3 的局面下，登场先增根并强化自己，立刻封印、攻击为 0、突袭无效 | 玩家没有在登场效果中间插入攻击的窗口 |
| C 方案用 `param:"hp"` 给古木预存生命、保留攻击 | 古木来源、己方目标仍自动吃成长增幅；基础 +2 在根 4、疯长 1 时变成 +12，并封印、攻击归零 | 快铺“先铺血再选一个封印”的核心步骤不成立 |

`hp` / `both` 决定改哪些属性，**不能排除古木来源的成长增幅**。C 文档对 `wood_transplant`、`wood_canopy_moth` 等路线的说明需要据此重写；这两张属于文档方案，未在已检查的 legacy 卡池中找到，复现使用方案声明的效果与真实古木来源，而非宣称它们已入库。

这不意味着快铺和厚养永远不能区分。区别需要来自实际可保留的攻击单位、载体数量、施加成长的时点、独立单位提供的防守、重建速度及对不同解法的取舍。给封印单位再堆失效关键词不能承担这些职责。

### 1.3 “生命支付”的实现和风险描述不成立

v1 枯骨作薪把 `LOSE_LIFE 2` 写成自己付血。当前 `LoseLife` 总是改变对手生命，即使效果目标写 `SELF` 也如此。复现结果：己方 20 不变，对方 20→18。

当前规则又明确规定玩家生命池本身不是胜负条件。因此“掉到 10 血就是濒死风险”“以血换折扣”不能直接套用通常卡牌游戏的生命经济；必须说明它具体损失哪种现有能力或资源。否则既没支付方案说的代价，又把生命门槛描述成了不存在的致死风险。此项属于 v1 问题，不把已经改过的 v2 卡逐张算作同一错误。

### 1.4 部分候选文本与可执行数据未完成对应

- legacy 的 `wood_trueroot` 文本写“扎根 3，抽 1”，实际只有 `ADD_ROOT 3`。放入可抽卡牌复现后，手牌仍是 0。
- `generals.json` 的 12 张卡全部缺 `faction`，并全部使用 `fx` 而非 `onPlayEffects`，不能直接交给当前 `CardCatalog`。例如“枯誓”文本要求手牌不超过 2，效果却用 `HAND_GE_1`。这是尚待转换和核对的候选文件，不是已证明正在污染生产卡池的 12 张卡。
- C 文档将“3 血单位治疗 4”举例为“3→7 血挡 AOE”，但它自己同时承认治疗受生命上限限制。治疗应按可恢复的伤量计价，不能当作提升生命上限。

这些问题会改变单卡功能和卡组节奏。在文本、数据、结算三者对应之前，对整条路线下强弱结论会混入实现缺失。

## 2. 成长牌的定价遗漏了关键放大方式

当前成长按**每一段 BUFF**计算 `(基础量 + 扎根) × 2^疯长`，不是将整张卡基础量相加后只增幅一次。

加载实际 legacy `wood_yearly_ritual`，其三段基础增量为 2、2、3。在扎根 20、疯长 3 的局面，对同一合法载体累计加血为：

`(2+20)×8 + (2+20)×8 + (3+20)×8 = 536`

同样基础总量 7，若只有一段则是 `(7+20)×8 = 216`。

**重复段数本身就在重复兑现扎根收益。**这不自动证明该牌必须削弱：上述局面需要先积累成长，512 仍在规定时点检查，敌方是否有响应也要看流程。但只用“基础值 7 / 惩罚值”或“大卡是小卡的几倍”定价明显漏项。

建议按几个真实可达局面比较：前期、根已累积但疯长未满、疯长满层、载体被拆后的重建。记录整张卡有效推进量、跨越 512 的时点、对方实际响应机会和未达门槛时的用途。尤其要区分：

- 多个小载体共同受益，与一个载体立即接近终点。
- 条件由本卡前一段效果自己满足，与需要前几回合经营才能满足。
- 可稳定兑现的收益，与容易被特定对手拆掉的收益。

仅增加条件名称、BUFF 段数或更大的数值，不足以产生新的构筑路线。

## 3. 胜率证据不能支撑当前调整力度

### 3.1 “1 点惩罚≈30 个百分点”是错误的推广

旧报告同时给 **19 张便宜卡各加 1**，这会改变一套卡组中许多张实际打出的牌，不是只改一张牌、一次出牌或卡组总费用 1 点。结果可以提示对整批低费曲线敏感，不能当作每点费用固定兑换胜率的系数。

`PL_FINAL_DECK_2026-09-24.md` 顶部已明确撤回旧 Java 数字的当前规则效力，因为该批实验缺 T1。最新动态报告仍把这个 30 点系数和新的 C# 排名一起用来论证高费牌调整，证据链没有恢复。

“按费用选便宜牌能赢过人工设计牌组”有诊断价值，但还可能包含：人工牌组功能未实现、AI 不会走目标路线、标签与抽牌差异、卡组组成差异、对手样本偏差。它不能独自排除这些因素，更不能证明卡牌质量无关紧要。

### 3.2 v2 实验没有验证古木成长路线

现存 `run_v2_dyn.txt` / `run_v2_static.txt` 各 5 组、每组 180 局：

| 卡组 | 动态池胜率 | 去条件池胜率 | 两池各自的“达 512”记录 |
|---|---:|---:|---:|
| v2_00 | 54.4% | 54.4% | 0/180 |
| v2_02 | 51.7% | 51.7% | 0/180 |
| v2_04 | 45.6% | 46.1% | 0/180 |
| v2_06 | 41.7% | 41.7% | 0/180 |
| v2_08 | 47.2% | 45.0% | 0/180 |

这些差异不足以证明方案改进或退步。尤其所有组的封印中位数都是 0，实验没有展示快铺、厚养或成长终结按设计运行。统计读取的是**对局退出时**最高封印生命，不是全过程峰值；应同时记录轨迹和最终获胜条件，避免把“终局没有载体”当作“全局没有推进”。多种获胜方式可以合法存在，但必须知道这些胜利实际走了哪条路径。

### 3.3 探针存在策略和统计限制

`build-output/wood-probe/Program.cs`：

- 明确跳过盖放伏兵，而 v1/v2 有依赖己方伏兵存在的收益卡。它无法公平评价伏兵路线。
- 源码自己记录旧固定优先策略无法区分卡组质量，随后加入 `WeightedPlaystyle`；现存 v2 日志没有新版输出的 `AI 排序` 行，也没有构建哈希，不能当作新策略的验证结果。当前策略异常还会静默退回旧排序，应记录回退次数。
- 到步数、时间、回合上限可以退出而无胜者；调用者无条件把该局加进 `played`，只在己方胜者时计胜。于是未完成局进入胜率分母，且没有独立完成率统计。这是计数缺陷；本审查没有证明现存日志实际发生了多少次退出。
- v2 均为 60 张主牌加统领，共 61 张。正式规则是 59+1；现有生产预构筑也尚未迁移，属于共同遗留问题，应统一口径再比较，不能只纠正实验一边。
- v2 为补齐张数，部分廉价牌含 11–16 张同名副本。这适合作为密度压力实验，但不能直接代表普通构筑；没有据此虚构“最多 3 张”的正式限制。动态密度还同时更换卡牌职责、标签和曲线，不能仅归因为费用。

v2 的同一密度、同一牌组、两池去条件对照在形式上较清晰，值得保留；但底层折扣不起作用、策略和统计尚未核准，扩大局数只会放大不可靠结论。

## 4. 哪些方向可以保留，哪些需要转向

| 方向 | 判断 | 下一步应检验什么 |
|---|---|---|
| 让前几张成长牌立刻有反馈 | 保留 | 不是只堆计数器；低成长局面下是否有真实防守、推进或补牌用途 |
| 载体被拆后能够重建 | 保留 | 根/疯长已保留，缺的可能是载体与手牌；按实际损失补足，并保留对手解牌价值 |
| 高费牌承担区别于低费牌的职责 | 保留 | 是否买到紧急稳定、资源补充、集中推进或终结窗口，未满足条件时是否仍有可用价值 |
| 快铺、厚养、借力、时序四路线 | 目标可保留，当前实现依据不足 | 同一局面是否会选不同目标、出牌顺序、载体数量与反制手段；关键词或门槛不同本身不够 |
| 条件收益和动态费用 | 分开检验 | 先验证条件实际成立及效果执行；真要改变费用，另行明确支付前后与持续时点 |
| 全体高费减 1–2、继续增加大 BUFF | 暂缓 | 目前无法排除机制缺失和策略问题，没有可靠数字支持调整幅度 |

建议把下一轮收窄为 **12–18 张能实际加载和执行的古木原型**，围绕三种可辨认取舍组织：

1. 快铺：较早形成载体并推进，代价是更依赖场面和续牌。
2. 厚养：较少载体、较晚投入，依靠真实有效的外围防守或重建维持进度。
3. 对抗/时序：根据对方已呈现的局面或明确触发窗口兑换收益，承担误判或条件未满足的风险。

这是建议的试验组织方式，不是替 owner 冻结路线、数值或数量。先让每条路线有少数能跑通的核心牌，再决定是否需要扩成 100 张。保护与终结都应留下可读的对手响应机会，避免为了提高模拟胜率把整个阵营变成廉价无条件连出。

最低验证顺序：文本/JSON/结算一致 → 核心连招和反例 → 正式构筑口径 → 至少两种明确记录的策略、交换先后手 → 分开记录胜负条件、未完成局、成长轨迹与关键响应 → 少量真人回放。成本调整应在这个基础上做同牌组、同策略、同随机条件的对照，并说明样本不确定性。
