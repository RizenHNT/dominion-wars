## 1. 已确认的事实（Verified）

### V1. 策略不会 stall（64 个 ACTION 局面）

4 阵营两两对局 × 4 seeds = 16 组，每组推进到 AI 的 ACTION 阶段：

```
ACTION positions probed: 64
```

**64/64 都取到了动作。** 仪器不会静默丢边——丢边会让被丢的那一方在所有聚合数据里看起来更弱。

### V2. 只提交引擎广告过的动作，且引擎接受（1177 次提交）

```
actions submitted to the engine: 1177
self-discard plays rejected as unsubmittable: 6
```

**1177 次提交中，6 次被拒，全部是同一个已定位的契约缺口（见 V3），其余 1171 次全部被引擎接受**，
且**没有任何一次提交未被广告过**。断言被写成"除该缺口外必须为空"，且缺口的形状逐条校验
（必须带 `discardRequired`、必须带 `discardCandidateIds`、必须**不带** `selectedEntityIds`），
所以这个排除项**不可能悄悄扩大**去掩盖别的失败。

### V5. 【① Engine correctness】广告的 punish 永不小于引擎实际抽牌数（893 次比较）

```
punish comparisons: 893
  advertisement == engine draw (EXACT): 830
  engine drew FEWER than advertised   :  63
```

**893 次涉及 punish 的动作里，830 次（92.9%）广告值与引擎实际抽牌数精确相等，
63 次引擎抽得更少，0 次抽得更多。**

**为什么这条定律这样写**：我一开始要求"永远精确相等"，跑出 54 处不一致。
逐层追查后确认**引擎是对的、我的预期太天真**，共两个合法机制：

1. **FIZZLE**：对手牌库不足以支付该 punish 时，这次出牌**完全不抽牌**地结算
   （`PlayCardActionHandler`：`fizzle = !PunishToSelfDiscardThisTurn && cost > opponent.Deck.Count`）。
   广告**仍然发布这个 cost**，因为那是卡面声明值，只是没被支付。
2. **CAPACITY**：`DrawCards` 在无法洗牌时停止，以及在**顶部是不可抽的统领实体**时停止
   （`EffectRuntime.Cards.cs`）。

**我为自己第一版预期付出的代价**：我连续两次用**过期读数**推断合法短抽
（先猜"牌库空"，被数据否掉；再猜"统领在顶"，我的快照在结算中就已失效）。
最后改成断言**可无条件成立的那一半**：**引擎可以少抽，绝不能多抽。**

**方向很重要**：少抽意味着 AI 把 cost 读成 N、实际支付更小 ⇒
**高 punish 的牌会被测得比实际更贵**。对首轮平衡来说这是**安全方向**
（不会把强牌误判成弱牌），但它**不是 0 误差**，已计入 §5 限制。

### V6. 【① Engine correctness】账目恒等式在**跨洗牌**下精确成立（665 次检查）

```
accounting checks: 665
a deck cycle occurred in the sweep: True
```

665 次检查全部通过，且**横扫里确实发生过牌库循环**（否则这条就没测到洗牌）。

检查的是**精确相等**，不是近似：`accounted + visible == declared`，
以及 **`accounted` 必须等于引擎真实的隐藏牌数**（`hand + deck + ambush`，直接读引擎状态），
且若不等则**必须**伴随 mismatch note。

**这条为什么关键**：牌库循环把整个坟场搬回牌库。那些牌原本被算作**已公开消耗**，
必须回到隐藏池。若估算器继续当作已消耗，未见数就会**按返回牌堆的大小偏低**——
而且误差随对局长度增长，是平衡仪器最糟的误差形状。

**边界修正（新增，实测）**：这条恒等式的**第二个断言（`accounted` == 引擎隐藏牌数）是有条件的**，
不是无条件成立。用独立探针在 127 个真实局面上实测：

```
accounted + visibleInPool == 声明的总张数 : 127/127   ← 估算器自身账目，精确成立
accounted == 对手公开计数(手+牌库+埋伏)   :  14/127   ← 只有 14 个局面成立
出现 off-list 可见卡的局面对应数量        :  35/127   全部是 flame_leader
```

差的**固定就是 leader 卡**：它真实存在于对手的牌库/手牌里，却不在 60 张牌表内。
所以"声明的牌表能解释对手的全部暗牌"**不是**恒等式。V6 之所以能通过，是因为它允许
mismatch note 作为"accounted ≠ 引擎隐藏数"的解释——**该豁免必须保留，且必须写明原因**。
后果与量级见 §5 限制 7：概率人口多 1 张，轻微**稀释**，方向安全。

### V6b. 【① Engine correctness】投影的**每一个字段**与引擎精确相等（59000 次比较）

```
published-field comparisons: 59000
viewer-owns-hand identity checks: 1180
opponent-hand redaction checks: 1180
```

**两侧 viewer 都测**（同一局面投影两次），比较的是引擎自己的状态：

- 20 个计数/布尔字段逐一精确相等（生命、手牌数、牌库数、场面数、坟场数、埋伏数、循环胜场、
  root/rampant 层数、pull、提交队列、云栈，以及 punish delta / 本回合被惩罚抽牌 / 累计弃牌 /
  无伤回合数 / 本周期受伤 / 惩罚转自弃 / 保护 / 效果被否定）；
- **公开区域**（场面、坟场、提交队列、云栈）的**实体 id 序列**逐位相等——
  用的是**顺序比较而不是哈希**，因为顺序无关的聚合看不出"重排"这种投影错误；

### V4b. 【③ 更正】估算器不读**印刷费用**是设计边界；不读生命是**正确**的

本节此前与 V9 一起被写成"仪器缺输入"，**两处并列都是错的**，更正如下：

- **R3 印刷费用：不是缺陷，是边界。** 本游戏的费用体系是**惩罚值**（`printedPunish` / `effectivePunish`），
  不是法力制。"卡牌代价"这条路**是通的**：引擎在 `LegalActionGenerator.cs:63-66` 把 `punish` 广告出来，
  `ActionFeatures.cs:159` 读了它，**6 个出厂 playstyle 里有 5 个给了非零权重**（−1/−3/−5/−6/−12）。
  只有 `default` 给了 0。所以正确表述是：**估算器不读印刷费用（设计如此），动作的实际代价是读的。**
- **R4 生命：不是缺陷，是正确的。** "对手可能持有什么"是对手牌库的客观事实，**与我的生命无关**，
  因此血量变化时读数不动**正是应有行为**。R4 的 1094 次比较零变化，应读作**通过**，不是"缺输入"。


这两条与 V9 是**同一个盲区**：仪器对"这局离结束还有多近"没有输入。

### V10. 【③ 规则可判定的劣招】自我毁灭式交换 4/4 被避免

```
self-defeating-trade positions probed: 4
  kept the material instead: 4
  seed 1: chose PLAY_CARD/wood_bark instead of the self-defeating trade
  seed 2: chose PLAY_CARD/wood_seed instead of the self-defeating trade
```

**为什么这一条和其它"劣招"证据不同**：本报告里其它案例（V4、V7）最后**都是价值偏好**——
偏好出牌胜过结束回合、偏好出牌胜过不造成伤害的攻击。**偏好可以争论。这一条不能。**

用 **1/1** 去攻击 **10/10**：攻击者死、防御者毫发无伤 —— **纯粹的兵力净损失**，
**没有任何权重表能把它算成好棋**。判据完全由引擎自己的数字给出（攻击力低于对方生命）。

**4/4 全部避免**，改选其它动作。**这是 ③ 里唯一"规则上确定错误"的正面案例**，
补上了此前"劣招证据全落在偏好上"的缺口。

### V11. 【④ 2-ply】预测的威胁位移与估算器自己的读数**精确一致**（66 次比较）

```
2-ply threat-shift comparisons: 66
```

2-ply 的核心一致性定律：预测器声称的"这一步之后威胁变成多少"，
必须**等于估算器自己对那个预测手牌规模的读数**。

**为什么可判定而不是见仁见智**：两者都是对**公开数据**做的算术。若不一致，
**必有一个是错的**；而一个与自己依赖的 1-ply 组件对不上的 2-ply 读数，会让任何基于它的决策失真。
**66/66 精确相等。**

### V12. 【④ 2-ply】更多牌流**永不降低**预测威胁（28 次比较）

```
flow-monotonicity comparisons: 28
```

给对手 **5** 张所预测的威胁，**从不低于**给 **1** 张所预测的。
这是变质测试在 2-ply 上的对应物：**后果的方向必须跟从原因的方向**。
方向若搞反，高 punish 的招会被显得**更安全** —— 正是会毁掉平衡测量的那种倒转。

### V13. 【④】预测器**拒绝编造**自己对胜利轴的推进（7 个动作）

```
moves checked for honest refusal: 7
```

每个动作的 `MyObjectiveNote` 都**非空**：步后距离**报告为未知并附原因**，
因为广告没有描述该动作的效果如何推进己方胜利轴。
**报 0 会被读成"这步不推进我的胜利"，那是一句自信的假话。**
这一条把"拒绝编造"变成可断言的性质，而不是注释里的承诺。

### V3. 【真缺陷】自弃牌类 PLAY_CARD 按广告内容**无法提交**

```
machine vs sea: accepted=False reason=action.discard_selection_required
  payloadKeys=[punish, discardRequired, discardCandidateIds]
```

玩家处于 `PunishToSelfDiscardThisTurn` 时，引擎广告的 `PLAY_CARD` 带
`discardRequired`（要弃几张）+ `discardCandidateIds`（可弃哪些）。
但**没有任何提交方式能满足它**：

1. 网关从 **`selectedEntityIds`** 读选择（`RuntimeMatchGateway.cs:396`）；
2. `RuntimeActionBoundary.Validate` 要求提交的 payload **等于**广告 payload
   （`!ValuesEqual(advertised.Payload, action.Payload)` → `action.advertisement_mismatch`），
   所以提交方**不能自己加**这个字段——我实测过，加了就被边界拒绝；
3. 网关的"候选集桥接"只对 **DISCARD 阶段自己的动作**生效，**不覆盖 PLAY_CARD**。

**后果**：该 play 每次提交都被拒，策略会**重复选中同一个动作**，形成拒绝循环而不是打牌。
**实测影响面**：V6 的 665 次扫地推进**就是在这一点上被迫停止的**
（`sweep ended early: ALL_REJECTED ... reason=action.discard_selection_required`），
所以任何涉及 punish→自弃机制的对局都会**截断**，长局数据尤其不可信。

**性质**：引擎广告 ↔ 网关之间的**契约缺口**，不是策略算错。
**我没有在适配层"修"它**：在本层只有两条路——破坏边界相等规则，或**替引擎凭空挑一个弃牌**，
两条都违反 AI 只能选广告动作的边界。应由引擎给这类 play 广告一个可提交的 wire selection，
或由网关把桥接扩展到 PLAY_CARD。**属规则/契约层，需 owner 定夺。**

**测试**：`SelfDiscardPlayIsUnsubmittableAsAdvertised` 断言该缺口**存在**。
一旦有人修好，这个测试会失败——**故意的信号**，提醒更新本条。

### V4. 【限制，非缺陷】punish 在出厂权重里权重为 0

```
inert play flame_double punish=2 rank=2 score=500 features[board=1x500 spend_card=1x0 punish=2x0]
inert play flame_rain   punish=4 rank=4 score=500 features[board=1x500 spend_card=1x0 punish=4x0]
END_TURN                           score=50  rank=5;  punish weight=0
```

把牌的效果**全部剥掉**（随从除外——召唤身体是真实效果），这些 play 仍然排在
`END_TURN` **之前**。两个模型性质共同造成：

1. **`board` 对每一个 PLAY_CARD 都置 1**（`ActionFeatures.Of`：`[Board] = isPlay ? 1 : 0`）。
   它的含义是"这是个出牌动作"，**不是**"这次出牌改善了场面"。权重 500 对 `end_turn` 的 50，
   于是**任何**出牌都压过结束回合，哪怕效果被彻底移除、哪怕纯属付出。
2. **`punish` 出厂权重为 0**，且注册表自己写明是刻意的
   （"the features the default prices at zero are the ones it was blind to (punish, ...)"）。

**对平衡测量的含义（直说）**：**出厂仪器不会选择克制。**
它会往自己的 punish 里打，因为它的目标函数里没有任何一项说不要。
所以**任何"靠吃惩罚值生存"的牌组，或任何弱点为"送对手牌"的牌，都会被系统性测得偏好**——
驾驶员从不拒付这个成本。

**这必须在报告里声明为限制，而不是一个可以信的数字。**
测试 `InertPlaysOutrankEndingTheTurnAndPunishIsPricedAtZero` 以**特征化**（而非"应当如此"）的形式
钉住该性质：若有人给 punish 定价或不再把所有出牌当场面价值，测试会失败，提醒更新本条。

### V7. 【③ 已定性：**不是漏必杀**】广告的核心攻击 12/12 被放弃，但**打了也没伤害**


2. 改成 **1 生命**后仍假设会赢 —— 仍然无法确认；

**结论：这里根本没有必杀可漏。** 我先前那 12 条 "missed kill" 每一条都是**错的指控**。

**该偏好是模型自身权重预测出来的**，所以它是一条关于**仪器重视什么**的陈述，
属于限制，**不属于"AI 会送掉比赛"的指控**。

## 2.7 策略稳健性（⑥ 完成）—— 含**噪声底线**

⑦ 换的是**策略**，⑥ 换的是**局面 / 牌序 / 座位**。这里最有价值的产出是**噪声底线**。

### V19.【本轮最关键的数字】只换 seed，排序一致性只有 **80.9%**

```
cards observed by both halves: 72
seed-half ordering agreement: 2066/2555 = 80.9 %
```

把 8 个 seed 拆成两个**互不相交**的半集（1–4 与 5–8），**设置完全相同**，只换采样：

**两次采样之间，约 19% 的"哪张牌更受偏好"判断会翻转。**

**这个数字决定了什么可以说**：
- 本样本量下，**选择率接近的两张牌，仪器分不出来**。把它们的排序当成发现，
  是**把采样噪声当信号**。
- 只有**差距明显大于**这一翻转率的卡片差异才值得写成结论。

**这是对使用者最实用的一条限制，比任何单项"通过"都重要。**

### V20. 换座位顺序：86.5%（不反转）

```
seat 0 first vs seat 1 first ordering agreement: 2211/2556 = 86.5 %
```

谁先手是真实的结构性优势，所以只在一个座位顺序下成立的读数**不稳健**。

### V21. 换起手手牌数：89.3%（不反转）

```
opening hand 4 vs 6 ordering agreement: 2283/2556 = 89.3 %
```

起手 4 张 vs 6 张是**不同的局面形态**而非同一局面的不同采样，所以只主张"**高于随机、不反转**"。

### V22. 非空洞守卫：确实有排序可复现

```
cards observed: 72
  selection-rate range: 1.20 % .. 11.42 % (spread 10.22 %)
  distinct rates: 72
```

**72 张牌、72 个互不相同的选择率，跨度 10.22 个百分点。**
若所有牌读数都一样，上面的"一致性"会平凡地等于 100%，什么也证明不了。

### 四种"换皮"测试的共同结论

| 换什么 | 排序一致性 |
|---|---|
| **只换 seed（设置完全相同）** | **80.9%** ← 噪声底线 |
| 换策略（⑦，6 个出厂 policy） | 77.6% |
| 换座位顺序 | 86.5% |
| 换起手手牌数 | 89.3% |

**全部高于 50%，且全部低于 100%** —— 读数**有共享信号，但带明显噪声**。

**换策略（77.6%）比只换 seed（80.9%）更容易改变结论**，说明策略差异是**真的**，
但它与采样噪声**是同一量级** —— 所以**任何单一 policy、单一样本量的卡片级结论都必须带这个保留**。

**站在必杀之下，把生命从 20 改成 1，策略给出的 51 个候选动作的排序一字不差。**
这就是 V9 的根因**被独立测出来**：不是"它算错了生死"，而是**它根本不看生死** ——
不存在 `RiskOfDying`、`LethalIncoming`、`SurvivalMargin` 这类输入。

R6 是**可证伪的对照**（写成"选择会/不会随生命改变"的观测，而不是断言某个方向），
结论与 V9 相互独立：V9 说"有防御也不做"，R6 说"连生命都看不见"。

**读数口径说明**：本节数字取自最终门禁运行（`build-output/pl-ai-replay/gate-final.xml`）。
本 fixture 在定稿前跑过一版**较早的修订**，其 R1 是 `kindComparisons=550 / strictIncreasesInHand=383`、
R4 是 `kindComparisons=1100`；定稿版（R1 改为只统计真正携带威胁类的比较）为
`547 / 474`、`1094`。**两版的定性结论完全一致**（R1 单调、R4 零变化），差异只在统计口径，
故以最终门禁的数字为准。R6 在定稿版中 `result="Passed"`，其 stdout 已抄录在上面。

| 对局 | 决策数 | 手牌最大（本方） | 手牌最大（对手） | 结果 |
|---|---|---|---|---|
| machine vs sea seed 3 | 20 | 17 | 16 | 未结束于第 7 回合 |

**同时必须写明的限制**：加上限后手牌**仍然会涨到十几张**。
这是结算规则本身的结果（惩罚收入大于每回合 2 次出牌的消耗），不是第二次失控，

### Va1. 提高 punish 不会让动作更有吸引力（变质测试）

4 副牌组，同一位置同一 seed、同一驱动，唯一变量是"所有 punish>0 的牌 +5"：

**两条方法学修正（都是我自己的错，记录在案）：**

   跑出 18 条假违规。已修正为 `if (after >= before) continue;`（rank 越小越优）。
2. 我第一版**跨不同 seed 的对局比较动作**，那是比较两个不同局面，证不了任何事。
   已改为**同一位置同一 seed**，并把动作按**稳定身份**（type+card+target）匹配，

把对手**隐藏手牌内容**改成与之公开计数矛盾的两张 `wood_giant`，策略的**动作类型与 actionId 均不变**。
即策略只读公开信息。**这是单点检查，非全量**（未做随机化对抗扫描）。

### Va3. 广告的胜利轴会被执行

`machine_leader` 以 `PULL_COUNT` 达 6 获胜；当引擎广告 `PULL` 且快照发布了该目标时，
策略选择 `PULL`，且发布的目标 metric = `PULL_COUNT`。
（该位置未广告 PULL 时会 `Assert.Pass` 跳过——仍未充分覆盖，见 §4。）

## 5. 已测出的已知限制（Known limitations）

1. ~~**【最严重】仪器看不见自己会死**~~ —— **已撤回，不列为限制**（2026-09-12 更正）。
   理由：按 owner 的规则**生命池不是胜利条件**（`RULES.md §1` 只有两条胜利路径），
   且在统领在场时玩家生命**不可被攻击**（`AttackTargetPolicy`）。所以"站着就会死"的局面
   **在当前规则下不存在**，AI 不去看生命是**正确**行为。
   原先引用的三条"证据"（4/4 不救、R6 的 107 局面零变化、R4 的 1094 次零变化）
   在更正后应读作**行为正确性证据**，而非缺陷证据。详见 V9、V4b。
   附带修复：引擎里那条**真缺陷**（玩家生命归零判负，`win.enemy_life_zero`）**已删除**，
   `PlayerLife` 默认值已改为 `null`。
2. **仪器不会克制**（V4）。`default` 的 `punish` 权重 0 + 所有出牌都算场面价值 ⇒ 任何"送对手牌"的代价
   在**默认策略**的目标里不存在。**靠吃惩罚生存的牌组会被默认策略测得偏好。**
   **注意范围**：6 个出厂 playstyle 里**有 5 个 `punish` 非零**（−1/−3/−5/−6/−12），只有 `default` 是 0。
   这是"**默认策略**不会克制"，不是"仪器不会克制"——此前本报告写宽了，此处更正。
3. ~~**费用与生命不是估算器的输入**~~ —— **改判为设计边界，不是限制**（V4b）。
   印刷费用不是本游戏的费用体系（费用 = 惩罚值，且**估算器读得到**：`payload["punish"]`）；
   生命不是胜利资源，"对手持有概率"与我的生命无关。**两者都不该进估算器。**
4. **自弃牌类 play 无法提交**（V3），涉及 punish→自弃机制的对局会**截断**
   （V6 的 665 次检查就是被迫停在这一点）。**在修好之前，凡涉及该机制的长局结论都不可信。**
   **进展 2026-09-12**：阻塞构建的编译错误已修（`RuntimeActionSelection.cs`），但**契约缺口未修** ——
   需决定"自弃牌是否强制显式选择"。详见 `PL_RULES_ERRATA_2026-09-12.md §5`。
5. **广告的 punish 不是已支付的 punish**（V5）：92.9% 精确相等，7.1% 引擎少抽。
   方向是"高 punish 牌被测得偏贵"——安全方向，但**不是 0 误差**。
6. **策略偏好出牌胜过攻击**（V7 已定性）：12/12 放弃广告的核心攻击，而控制组证明**打了也不造成生命伤害**，
   故**不是漏必杀**。但该偏好由权重结构决定（`board` 500 vs `damage` 120、`face` 0），
   意味着**仪器系统性低估"攻击/打脸"这一手**——凡强弱依赖进攻节奏的牌组都会被测得**偏弱**。
7. **对手的 leader 不在其"已声明牌表"里**（新测，证据 `build-output/pl-acct-probe/accounting-reconciliation.txt`）。
   用真实对局实测 127 个局面：
   - 估算器**自身**的账目恒等式 `accounted + visibleCopiesInPool == 声明的总张数`：**127/127 精确成立**；
   - 但 `accounted == 对手公开计数(手+牌库+埋伏)` **只有 14/127 成立**；
   - 差额**稳定为 +1**（例：`accounted 60` vs `observedHidden 61`；`48` vs `50`；`23` vs `24`），
     当 off-list 卡出现在公开区域时变成 +2；
   - 35 个局面出现 off-list 可见卡，**全部**是 `flame_leader`。
   **结论**：leader 卡真实存在于对手的牌库/手牌里，却不在 60 张牌表内。
   **含义**：估算器的概率人口比现实多 **1** 张 ⇒ 轻微**稀释**（估算偏保守），方向安全、量级很小，
   但**"声明的牌表能解释对手的全部暗牌"这个前提是不成立的**，
   报告与测试都不得再把它当作恒等式；引用 V6 时必须带上这个边界。
8. **实测样本面窄**：robustness 类证据只来自默认 policy、16 组对局、64 个 ACTION 局面；
   1-ply 只比了 2 次；必防只探了 4 个局面；必杀模式只探了 12 个局面。
9. **变质关系结论（§2.7b）**：R1 ✅（547 次比较 / 474 严格上升 / **0** 下降）、
   R2 ✅（37/37 严格下降 / **0** 上升）、R5 ✅（101/101 方向正确）**成立**；
   **R3 不可测（估算器无费用输入）**、**R4 断言成立但 1094 次比较读数零变化（生命不是输入）**。
   **"变质一致性"整体不成立** —— 不是因为关系被违反，而是因为**两个关键输入根本不存在**。
10. **胜利轴检查可能被跳过**（Va3 的 `Assert.Pass` 分支），需改为强制构造。
11. **工具限制：单测运行器不能按名字过滤**。`PlP0Runner` 的 `--filter` 只接受 NUnit filter XML，
    传裸类名/测试名会返回 `total=0`（本轮实测 `<test>`/`<cat>` 两种写法都不匹配）。
    所以每次验证都只能跑**整个程序集**（约 870 项、90 秒内），这既拖慢迭代，
    也意味着**失败项必须从结果 XML 里读**，不能靠过滤输出判断。
12. **R5 需要 leader 已显形**：leader 卡从牌库被抽到才进入可见的 leader 区
    （`EffectRuntime.Cards.cs` 的 `ManifestLeader`），所以对局**第一个 ACTION 阶段**的
    leader 区是空的、没有任何一方胜利条件可知。R5 因此按"每个可见 leader 的回合"取样；
    在更早的一版里它正好只取了首个 ACTION 局面，于是 `comparisons=0` —— **要记录的取样教训**。

## 7. 总体判定（Final judgement）

判据不是"AI 是否最优"，而是两条：
(a) 它是否**不会系统性地把明显错误当成正确**；
(b) 当卡牌强度 / 费用 / 制胜速度**真的变了**时，它的测量是否**朝正确方向移动**。

### 7.1 结论（**已于 2026-09-12 更正**）

> **本节原先的结论是「不能认定最低可信度已达成」，理由是 V9 那条"AI 面对必杀不救"的反例。
> 该反例已撤回：它建立在一个规则不允许的局面上（见 V9）。下面是与更正后证据一致的结论。**

**没有发现"系统性把明显错误当成正确"的证据。** (a) 目前**不成立为反例**：

- 唯一一条"规则上确定错误"的测试（V10 自我毁灭式交换）是 **4/4 被避免**的。
- V9 那条曾被当作反例的，实为**我的测试断言了一条游戏没有的规则**：生命池不是胜利条件，
  且在统领在场时玩家生命不可被攻击，所以那个局面里**不存在必杀**，AI 不防御是对的。
- 引擎里**确实有一条真缺陷**（玩家生命归零判负），**已删除**；规则书与引擎现已对齐。

**(b) 成立**：⑨ 三项（伤害↑ / 费用↓ / 胜利条件变近）方向全部正确，测量确实随真实变化移动。

**但 ③ 的覆盖必须如实写窄**：战术能力这一项**不再是"完成"**，也不是"失败"，而是**部分覆盖** ——
缺一条**可测的"必防"定义**。原因是规则层面就不存在"站着就会死"的局面（生命池不是胜利资源，
统领在场时不可被攻击，而统领不在场时有门限保护把致败数值钳住）。**这不是 AI 的缺口，是这一类
测试在当前规则下无法构造。** 若日后把生命池启用为胜利轴（§12.5 已登记为预想方案），
"必防"才成为可测项，届时应新增测试而不是复用被删掉的那个。

同时必须**如实记录成立的部分**：

| 类别 | 内容 |
|---|---|
