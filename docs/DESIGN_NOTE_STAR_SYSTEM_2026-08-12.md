# 星位体系设计笔记

> 状态：人类负责人提出的待评估方向。本文只整理讨论内容，不代表已批准规则、平衡或实现完成。

## 1. 核心定位

“星位”不是跨阵营统领，也不是额外统领槽位，而是一套可以由各阵营分别开发的强化体系，类似以核心卡牌和支援卡围绕统领构筑的主题包。

- 一套牌仍然只有一个统领。
- 各阵营可以推出本阵营的星位统领、星位支援卡和专属星图。
- 星位卡可以围绕阵营特色设计；共同点是参与星位、星图排列或星位保护。
- 未来可以作为补充包主题持续扩展，而不是一次性关键词。

## 2. 星位区与实际场地

当前较有价值的方向是：星位区显示目标星图，玩家在普通场地上复现它。

- 星位区是“图纸/目标展示区”，不是卡牌存放区。
- 星图可以从一组合法模板中随机出现，但不能随机生成牌组无法完成的要求。
- 实际卡牌仍留在普通场地，可以攻击、被破坏、被沉默和被保护。
- 星图可以要求精确位置、相邻关系、中心卡、方向或保护回合。
- 完成星图后，可以获得增益、破坏王城屏障、破坏随从，最高难度的星位可以作为该统领的胜利条件。

这保留了“排列”和“保护”两个核心乐趣，也让对手能直接干扰关键位置。

## 3. 条件的精确程度

星位不必全部使用宽泛字段。指定卡名本身可以是构筑难度和故事感的一部分。

建议未来数据层区分：

- `cardId`：要求某一张具体卡。
- `cardFamilyId`：允许原版与强化版共享星位身份。
- `starRequirement`：描述该星图中的要求、位置和关系。

普通卡牌检索可以使用阵营、种族和关键词；高难度星位可以要求卡名或卡牌系列；传说级星位甚至可以要求指定版本。这样既能保留难度，也能允许补充包继续推出强化卡。

## 4. 信息与调整玩法

不同星位统领可以有不同的信息规则：

- 完全确认：直接显示完整星图，适合稳定构筑。
- 部分确认：只显示部分位置和线索，玩家需要观测或推测。
- 可调整：特定低费星位单位登场时，可以替换、调换或揭示一个星位位置。

信息不应完全依赖盲猜；未知位置最好提供阵营、类型、位置或关系方面的线索。一次调整最好只影响一个位置，且在玩家已经投入部分组件后设置锁定或调整限制，避免反复刷新最简单的星图。

## 5. 后续封锁体系

后续补充包可以加入专门擅长封锁区域的单位体系，而不是给所有星位统一增加封锁规则。

- 单位通过封锁左、中、右或其他特定区域建立组合。
- 完成指定封锁组合或条件后，可以让本套牌原本的统领登场/觉醒。
- 这不会增加第二个统领；仍然遵守“一套牌一个统领”。
- 封锁可以成为该阵营自己的构筑主题，也可以与某些星图发生联动。

需要重点控制封锁的可玩性：封锁应有清晰的解锁、转移或反制方式，避免玩家完全无法行动。

## 6. 暂不决定的事项

- 星图随机是在统领登场时生成，还是从统领专属星图牌中揭示。
- 星位卡摆放是否允许自由移动，还是必须通过效果移动。
- 星位完成需要维持一回合、一个阶段，还是立即结算。
- 部分确认星位给玩家多少线索。
- 星位失败后是否保留部分进度。
- 封锁体系与星位体系的关系，以及哪些阵营先获得该主题。

在这些问题确定前，不修改现有 Java 规则基线、C# 合约或正式卡牌数据。
