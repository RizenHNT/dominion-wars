# VIS-01：视觉语言定稿与可运行样板生产 Goal

## 本轮补充：在线资源与统一设计验收

用户允许AI生成素材，也允许可商业使用的在线资源。采用项目已有素材、AI生成、原创矢量/建模、许可合适的在线素材混合生产；不以来源决定美术质量。探索阶段允许完整AI效果图，最终界面须具有真实信息、可编辑文字与可独立替换组件。

每项在线素材入库前记录作者/来源URL、具体许可及核对日期、下载或购买凭证、允许修改/嵌入游戏/宣传/付费外观的用途、署名要求和再分发限制。允许商用不自动代表允许将原素材独立转售为卡图包或皮肤。字体许可单列；AI输入参考的上传、改编权限与输出许可分开核对。免费合规资源可按本轮授权选用；新订阅和费用不由此自动获批。

统一处理链：候选素材→许可审核→对照已确认Style Frame→调整色域、线条、纹理尺度、光照/透视、裁切与信息安全区→放入真实卡框和场景→联系表及实机验收。不能只盖一层网点滤镜就判定统一；不适配的素材更换或重做。

原创与统一由以下可见证据评审：

- 将参考拆成网格、字级、色块、印刷与运动等方法，创作本项目组件；不直接沿用某游戏的整套布局、图标或资产。
- 形成三个固定识别特征的候选，例如参数式数值栏、编号信息条、标签展开转场；具体形式必须由Style Frame确认，不在此视为定稿。
- 五类界面去掉Logo后仍共享组件与运动规则；与参考并排检查是否仅剩配色变化或复刻轮廓。此为辅助判断，不是法律上的原创证明。
- UI层统一字体、网格、色彩语义、线宽；插画层统一色域、线条/明暗处理和印刷密度；动效层统一进入方向、节奏和中断方式。阵营可保留各自构图和内容差异。
- 增补一张未参与定稿的真实卡与一种新状态，验证规则能延伸；若必须重新发明整套样式，退回规范补充。

## 补充澄清：AI创作范围、原创性与商用

用户明确没有禁止AI生成素材。允许AI广泛参与概念探索、完整Style Frame候选、卡图、背景、纹理、卡框、图标、动效构思和辅助建模；具体工具须具备对应输出能力。整屏生成可用于探索和比较，但不能直接冒充可编辑、可运行的最终UI。此前“AI只负责子任务”的表述仅适用于最终资源装配阶段，不限制探索阶段。

原创性目标是形成可识别的本项目设计系统，不承诺历史上从未存在相似风格。用三步验证：先从有出处的时代参考提取视觉规则；再在同布局中进行有限变量的原创构图探索；最后用战斗/详情/构筑/伤害/胜利横向对比验证共同规则。去掉游戏Logo后仍应有共同身份，各页又要有符合操作目的的构图。安排一轮主要同类作品相似性人工检查；这不是法律上的不侵权保证。

统一分为固定层与变化层：固定字体层级、信息语义、网格关系、状态符号和运动逻辑；允许阵营插画、局部色域、材质及页面重心变化。每种变量须有适用范围。用户认可的样本与规则共同构成基线，单一提示词或AI自评分不能替代。

## 目标

将人类负责人本轮给出的“90年代中国大陆现代视觉经验 × 构成主义 × 当代游戏动态图形”转化为可编辑、可验证、可复用的视觉系统，完成战斗、卡牌详情、卡组构筑、伤害结算、胜利五类 Style Frame，并以真实 Unity 战斗样板证明读牌、交互、动效与资源替换可用。为后续其余页面、PV和宣传建立同源生产规范。

完成含义：人类确认视觉方向，素材有独立源文件，样板在当前 Unity 中通过交互和视觉验证，默认皮肤可回退。不是“生成一张好看图片”或“全部91张卡图已完成”。本方案不承诺零返工，使用分阶段验收控制返工成本。

## 研究结论与证据边界

公开流程支持“参考/风格样本→受约束生成→修整→导出→集成”，不支持一次整屏生成即可交付。Scenario的工作流文档描述将生成、修整、扩展、放大串联后重复使用；客户页面展示游戏资源变体与营销用途，属于供应商案例，速度与质量收益未经本项目验证。

因此首轮使用现有图像生成能力，不购买Scenario、Firefly等额外服务。研究其生产方法，不将厂商演示视为效果保证。生成图像具有随机性，重跑相同提示词不保证像素复现；应保存最终资产、版本、来源与哈希。

## 工具决策

| 工作 | 主工具/格式 | 原因与落地条件 |
|---|---|---|
| 精确平面设计 | Inkscape + 分组SVG | 文字、数字、框、图形独立；可以本地编辑和批量导出。先验证字体、滤镜和PNG导出往返 |
| UI规格 | 独立设计token文件 + 组件规格 + SVG | 颜色、字号、间距、线宽、倾角、状态有共同来源，不逐页凭感觉生成 |
| 卡图/材质探索 | 已有内置图像生成工具 | 每次只生成明确资产，约束构图、色彩、尺寸与透明背景；实际调用与模型标识如实记录，不将图像工具宣传为GPT6原生建模 |
| 位图修整 | Krita，或已验证可用的同类本地工具 | 用分层源文件、遮罩、颜色调整处理素材；当前会话没有原生桌面控制能力，不能承诺无人值守完成任意GUI修图。优先在生成工具中做定向修改，无法验收的源文件任务明确阻塞 |
| 动效草模 | 本地HTML/CSS/SVG | 快速测试几何遮罩与节奏，明显标注模拟；不引入玩法规则 |
| 真实交互与最终动效 | 当前Unity UI体系 | 沿用现有组件与事件边界，不为美术换UI框架；HTML动效不能替代Unity验收 |
| 3D辅助 | Blender（按需） | 只做需一致视角/光照的机壳、构件、材质；简单UI形状直接矢量制作；先验证可脚本生成和导出 |
| 评审 | 本地联系表、图片、设计说明 | Canva可作为评审展示副本，不能成为Unity资源唯一源文件 |

Penpot有组件实例和设计token支持，适合今后多人协作，但首轮不新增云端设计依赖。Figma/Penpot/Canva若之后采用，必须验证连接、编辑、导出往返，并指定唯一主文件，避免与SVG双向漂移。新服务、付费、项目文件上传按既有边界处理。

Inkscape暂不可用时，可以先写标准SVG并用本地浏览器预览；完成门禁仍须通过真实编辑器打开/修改/导出往返，不能把浏览器截图当作已验证设计源文件。

## 阶段与交付门禁

### G0：素材/工具/玩法审计

交付：ASSET_AUDIT.csv、TOOLS_PREFLIGHT.md、BATTLE_INFORMATION_MAP.md。

遍历项目素材及清单，分类为复用、需修整、占位、缺失；记录路径、尺寸、透明度、用途、来源、当前引用。不能只看到4张卡图便推断全库缺图。优先挑选当前真实卡牌覆盖长名称、长规则、普通卡、特殊状态。工具验证用临时测试件完成中文字体、图层、透明PNG和导出；不改变系统关联或卸载已有软件。

建立战斗信息图：双方手牌/场面/伏击、王城、生命、牌库/墓地、提交队列/云端、阶段、当前响应及主操作分别从何而来。读取实际可见性，禁止假设对方内容公开。

门禁：每个关键组件有数据来源；当前运行缺陷与视觉工作分开记录。已知玩法故障不阻碍参考研究，但阻止最终样板宣称可用。

### G1：证据板与结构试稿

交付：8–12份具体参考及来源、参考分析表、真实内容低保真战斗布局、同布局两种视觉试稿。

参考覆盖90年代包装/印刷、信息条/参数栏、公共材质/电脑设备。每份注明年代证据可信度与“提取什么”，不能拿不明年代的复古再创作当史料，也不能把他人图片直接混入生产素材。

两版共用真实内容和布局，仅比较主视觉组织：A以比分/信息条为重心，B以包装/参数栏为重心；都遵循最新要求，不另设世界观。交付比较表说明颜色、字重、色块比例、材质密度的差别。

H1人类评审：选择/修正方向和信息布局。允许混合具体优点，随后形成一份合并基线；未确认时不批量生产插画。人类不需要自己搜集参考，Codex负责准备可判断材料。

### G2：设计语言与五类Style Frame

交付：STYLE_BIBLE.md、design-tokens候选文件、组件状态表、可编辑SVG与PNG联系表。

五类：战斗、详情、构筑、伤害、胜利。其中战斗含普通/高信息密度两帧；伤害含前/中/后三帧；共至少8帧。使用现有真实卡名和规则。缺少真实触发数据时使用注明非权威的测试场景，不修改正式卡牌数据来迎合展示。

规格涵盖：字体文件与许可、字号层级、数字布局、网格、间距、线宽、倾角、色彩语义、纸材/网点强度、图标、状态、背景层和前景层。完整正文可编辑，生成图不能承载正式UI文字。

H2人类评审：认可静态语言和组件逻辑。保存版本号、文件清单和确认记录。后续局部问题局部修改，改变主色/字体/布局骨架才回到此门禁。

### G3：最小素材库与运动样板

交付：至少4张真实卡对应的风格样本（四阵营各1张）、1张卡背、3种基础材质样本（水磨石/纸/塑料）、1组公共区域装饰、通用组件状态库、3类可播放动效。

按已批准画面需要复用或制作，以上是最低覆盖，不要求重复生成已有合格素材。卡牌主体、背景、框、文字、状态独立；透明度和遮挡关系实际检查，不能将一张合成图另存分层格式冒充分层制作。

3类动效：整屏导航、伤害/阶段反馈、卡片展开详情。记录起止状态、进入方向、时长、缓动、遮罩、打断/连续触发行为以及Reduced Motion版本。先验证草模，再Unity落地。

H3人类评审：结合已定静态风格确认运动力度；此后同语法的常规动画不重复申请。

### G4：Unity真实样板与回退

正式执行前由PL收敛具体文件白名单；Codex沿现有UI组件接入。只实施战斗及详情、伤害、阶段、结算所需样板，构筑可先保留已审设计稿；其余页面不扩散实施。

保留默认资源映射，新增候选皮肤映射；切换卡图与背景后同一逻辑卡身份、点击区、事件与信息保持一致。没有实际外观切换入口时用测试夹具验证加载回退，不声称商城/所有权系统已经存在。

技术验收：当前项目所需构建/测试、隐藏信息、合法目标、非法拖放、长文、空区域、大队列、动画重入、减少动态、终局及恢复。若恢复语义仍待定，记录为未完成阻塞，不能由UI补造。

视觉验收：1440×900及1280×720真实操作截图与短录屏。关键内容无裁切；长规则可在详情完整阅读；手牌全可访问；目标尺寸满足合同；提示不遮住拖放；双方归属与数量明确；色彩不是唯一状态线索。

性能：在同一台机器、相同场景和配置测前后帧时间/内存。G0记录硬件与现有目标；若未有目标，提交具体性能预算由PL收敛后再验收，不能只写“流畅”或虚构60fps通过。

完成条件：PL审核范围符合、QA证据通过、人类视觉通过；产物可编辑、可重导出、可回退。未具备实时验证工具时G4保持未通过，不用代码审查替代实机。

## 防止AI模板化的生产纪律

1. 拒绝整屏文生图作为设计主文件。骨架由实际玩法及网格构成，AI只负责明确的视觉子任务。
2. 正向样本必须来自本次认可的参考和Style Frame；拒绝的旧稿标记REJECTED，不参与提示词或参考集。
3. 每个非通用元素须说明“来自哪个母题、帮助哪个信息/动作”。无意义编号、满屏标签和装饰性小字退回。
4. 五类画面使用同套token与组件。改主题参数应可一致重导出；不依赖每屏重新提示模型猜测风格。
5. 先做四阵营样本联系表，比较线条、色域、网点尺度、材质和构图。不合格不扩展到全卡库。
6. 每个生成任务记录assetId、用途、尺寸、参考版本、提示词、工具/可见模型名、候选、退回理由、选中版本。单项连续两轮无改善先定位问题，停止盲目重抽。
7. 高饱和与斜切有信息含义；静态阶段保持秩序，动态短暂改变重心。不要用金边、霓虹、仿古纸、统一圆角面板填空。
8. 接受与拒绝样本并排保存；审美评价必须由具体问题支撑，不用AI自评“9分”判定过关。
9. 人类定视觉，自动检查定尺寸/缺字/透明度/文件引用等；两类门禁独立。

## 资源可恢复与后续批量生产

候选目录：design/visual-language-v01/{references,source,frames,motion,exports}；报告放docs/visual-language-v01/。单一素材清单记录相对路径、版本、来源、许可/用途范围、哈希、导出参数、色彩空间、alpha、用途和logical asset ID。字体、图像许可逐项记录，网页参考不自动获得复用权。

不覆盖当前DAILY_GOAL，不直接运行已完成旧目标。启用前更新独立目标及允许文件范围，验证审计接力工具，再按仓库的PlanOnly/ApprovedPlan流程使用；设计门禁H1/H2/H3分别保存可见产物与决定。常规生成、修复和已批准范围内交接不重复确认。新订阅、新提供商、额外预算或配额耗尽停止相应付费步骤并报告。

预算控制为提案：每轮两种方案、单项两轮无改善即诊断、四阵营样本先行；未设金额或token预算，也未启动长期自动goal。工具失效只阻塞依赖步骤，继续参考/规格/已有资源工作，不私自更换付费模型。

## 本轮交付与下一步

本轮完成公开流程调查、环境与当前状态核对、这份可审阅Goal；没有安装软件、生成新素材、修改生产UI或启动模型接力。建议下一执行单元为G0+G1；第一件可见成果是有来源的参考板、真实战斗结构和两种同布局试稿。
